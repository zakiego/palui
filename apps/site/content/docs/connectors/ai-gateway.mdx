Kind: `model`. ai-gateway is a second model provider with the same shape as [CLIProxyAPI](/docs/connectors/cliproxy). Its main job is to be the fallback: it sits at the end of every role's failover chain, so a quota error or an outage on the main provider doesn't stop Palui.

## Connect

1. On the Connectors page, add ai-gateway.
2. Keep the default base URL if it runs on the Docker host, or change it.
3. Paste the API key (it starts with `zkg_`).
4. Press Test. Like CLIProxyAPI, it lists the models and makes a 1-token call per role.

## Settings

| Field | Default | Notes |
|---|---|---|
| Base URL | `http://host.docker.internal:8793` | ai-gateway on the Docker host |
| API key | | Secret. Write-only, shown masked. Logs redact `zkg_` keys. |
| Protocol per role | | `anthropic` or `openai`, same as CLIProxyAPI |

## Failover

On a 5xx, a 429 or a quota error from the connector ahead of it, Palui retries the step on ai-gateway. You set the order of each role's chain in Settings, under model roles and failover.

## Tools

None.

## Pause and remove

Pausing applies from the next turn and takes it out of every chain. If it was your only model connector that's on, the router sends the fixed "Model lagi off" reply until you turn one back on. Removing deletes the stored API key.
