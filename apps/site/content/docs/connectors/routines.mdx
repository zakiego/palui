Routines are flows now. A routine is a [flow](/docs/connectors/flows) with one schedule trigger and one step, and after the handover the routine tools edit flows. This page describes the routine shape, which the tools keep for one more release.

Kind: `skill`. Built in. A routine pairs a time source (when) with an action (what), plus an optional recap. Palui builds routines from chat out of these generic parts, so one feature covers medicine check-ins, habit tracking, a weekly review, bill reminders and times that change every day.

## Connect

Nothing to set up. Routines is a built-in skill and is created on first boot. Ask in chat:

- "ingetin minum obat jam 8 sama jam 8 malam, tanya udah diminum belum"
- "tiap waktu sholat tanya aku udah sholat belum, tanya lagi tiap 20 menit sampai waktu berikutnya"
- "tiap Jumat jam 4 sore suruh aku review minggu ini"

## The config model

| Part | Kinds | Notes |
|---|---|---|
| `source` | `times`, `rrule`, `tool` | `times`: fixed local times. `rrule`: one RFC 5545 rule with a start. `tool`: times read every day from a read-only connector tool. |
| `action` | `message`, `checkin`, `prompt` | `checkin` asks with your own answer options, re-asks every N minutes until a closing answer, up to a max, until a deadline. |
| `recap` | `off`, `daily`, `weekly` | A summary of the log at a set time. |
| `days` | `MO`..`SU` or null | Active weekdays. |
| `tz` | IANA zone | Default from Settings. |

A `tool` source has either `items` (a dotted field path per occurrence, like `times.fajr`, with a label and an offset in minutes) or `list` (an array of dated entries, like bills with a due date). `{{date}}` in its args becomes the local date the tool is called for.

Message text can use `{{name}}`, `{{label}}`, `{{time}}`, `{{date}}`, `{{answers}}` and `{{n}}` (the re-ask number).

## Tools

| Tool | What it does |
|---|---|
| `buat_rutinitas` | Create a routine. A tool source is read once first, so a wrong connector or field path fails right away. |
| `daftar_rutinitas` | List routines with their full config, next time and last source error |
| `ubah_rutinitas` | Change a routine. Applies from now on. |
| `jeda_rutinitas` | Pause (optionally until a date) or resume |
| `hapus_rutinitas` | Delete a routine and its log for good (destructive, always asks) |
| `jadikan_flow` | Turn a routine into a flow, keeping its schedule, open check-ins and log |
| `pratinjau_rutinitas` | Preview the next times of a routine or a draft source |
| `jawab_checkin` | Record an answer to a check-in |
| `riwayat_rutinitas` | The log and counts |

## Answering a check-in

- Telegram: the answer buttons.
- WhatsApp: quote the question and reply with an answer ("sudah", "belum", or one of the words you set).
- Anywhere: just say it. Open check-ins are in the model's context, so "udah" answers the newest one.

Buttons and exact quoted replies are handled by the router without the model.

## Safety

- A tool source only calls tools classified `read` (the saved class, else the server's `readOnlyHint`). It's called server-side on a timer, not through a turn.
- Tool results are data. Only values that parse as times are used, labels from a result are cut to one plain line, and a prompt routine fed by a tool source runs tainted.
- If the source fails, Palui retries with backoff, keeps using the last times that worked (and says so on the message), and tells you once a day.
- Each occurrence fires once, keyed by date and item, across restarts. After downtime, a check-in past its deadline or a message more than `lateGraceMin` late is logged as skipped.

## Pause and remove

Pausing the connector hides the tools from the model. Routines already set keep firing; pause one from chat to stop it.
