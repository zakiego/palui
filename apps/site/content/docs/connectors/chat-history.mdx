---
title: Chat history
description: The built-in Chat history skill lets Palui find your other chats and read their recent messages, read-only.
---

Kind: `skill`. Built in. Ask Palui about another chat and it can look it up and read what was said there: "cari chat grup keluarga terus rangkum obrolan terakhirnya" or "apa yang dibilang di chat Telegram kemarin?". It never writes to another chat.

## Connect

Nothing to set up. Chat history is a built-in skill and is created on first boot.

## What it can see

Each agent only sees the chats it answers in: the chats assigned to it, and for Palui every chat with no agent of its own. Palui can't find or read a group another agent answers in, and that agent can't read your DMs with Palui. Asking for another agent's chat by id or WhatsApp JID gets an error that says the chat belongs to another agent, with nothing from it. The dashboard's Chats page still shows every chat.

Within its own chats, an agent only reads what was stored:

- Your messages and Palui's replies.
- The text of a message you quoted, as a short `replyTo` preview.
- Webhook events, marked with the hook's name.
- Photos, voice notes and documents show up as a marker (`[gambar]`, `[audio]`, `[dokumen: tiket.pdf]`), never the file.

In a group with an agent, what everyone else said is stored too, with their names. WhatsApp contact cards are stored as `[contact: name, number]`, locations with their coordinates and polls with their options. Tool calls and internal summaries are skipped.

## Tools

| Tool | Class | What it does |
|---|---|---|
| `search_chats` | `read` | Find this agent's chats by title, WhatsApp JID, Telegram chat id or chat id, with an optional channel (`whatsapp`, `telegram`, `web`) and kind (`dm`, `group`) filter. Newest conversation first, at most 20. Each result has its channel, external id, title, kind, last message time and message count. |
| `search_this_chat` | `read` | Search older messages in the chat the turn is in, by a word or name. Matches message text, contact cards (`[contact: name, number]`), captions and the text of quoted messages, with who sent each one. The newest 20 matches by default (at most 50), optional `before` and `since`. Offered in every chat, groups too. |
| `read_chat` | `read` | Read one of this agent's chats by its chat id or an exact external id. The newest 30 messages by default (at most 100), returned oldest first. Optional `before` and `since` times and a text search. Each message is clipped at 500 characters. |

Times in and out are in your zone (Settings, default `Asia/Makassar`). Each tool's class decides when it needs approval. See [Tool classes](/docs/concepts/tool-classes).

## Safety

- Both tools are untrusted. Quoted text, group titles and webhook payloads come from other people, so reading them taints the turn and every `write` tool after it asks you first. See [The taint rule](/docs/concepts/taint-rule).
- `search_chats` and `read_chat` are offered only in a private chat with Palui: a DM or the web chat. In a group they don't exist, so another chat's messages can't be posted where other people read them.
- `search_this_chat` is offered in every chat, groups included, because it only reads the chat the turn is in. A number shared in a group only ever comes back to that group. Guests in a shared chat get it too, and its results taint the turn like the other two. Webhook turns never get it.
- Webhook summaries run with zero tools, so they never get these.
- Scheduled jobs do get them when the job's target chat is a DM or the web chat (a nightly "rangkum grup X" job works). Jobs already never get `destructive` tools and every `write` needs approval, and the result only goes to your own chat.

## Pause and remove

Pausing hides the tools. Nothing is deleted.
