Palui Agent uses [semantic versioning](https://semver.org). Each release is a git tag `vX.Y.Z` on `main`, and a running install reports its version as `version` in `GET /health`.

- While the version starts with `0.`, the v1 scope below is still being built. A minor bump (`0.2.0`) adds features or changes behavior. A patch bump (`0.1.1`) only fixes things.
- `1.0.0` is the release where the v1 scope is done. From then on, a major bump means you have to do something when you upgrade, and the release notes say what.
- Changes that need action from you on upgrade sit under "Breaking" in that release.

## Unreleased

### Added

- Each agent now has its own page (`/app/agents/<slug>`), opened from its row on the Agents page. It holds the profile, the shared-chat rules, the daily cap with today's usage, the recall container, its standing instructions (add, edit, switch off and delete them right there) and the chats it answers in, each with its Answer here switch. New agent asks only for a name, slug and persona, then opens that page.

### Changed

- The global daily token cap (Settings, Limits) can now be set to 0 to turn it off, the same as an agent's or a job's cap, so turns never pause on token use. `/status` shows `tanpa batas` when it's off.

### Fixed

- Raising the daily token cap or runs per hour (or setting the token cap to 0) now lifts a budget pause on the next message instead of at midnight, and `/status` shows the cap that applies now. Before, a pause stayed until midnight even after you raised the cap, and turns could fail once that pause ran out.

## 0.4.0 (2026-11-11)

### Added

- Tool search. When more tools are enabled than Tools per turn (Settings, Limits), Palui loads a core set and lists the rest by name. It finds what it needs with `palui__cari_tool` (keywords in any language or exact names), calls it in the same turn, and keeps it loaded for the rest of the conversation. However many skills and MCP servers you add, none of their tools get dropped. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Agents: named personas with their own instructions, recall memory, daily token cap and avatar (an uploaded photo, or an icon and a color). Give one to a WhatsApp or Telegram group, or to someone else's DM, from the new Agents and Chats pages or with `/agent <slug>`, and it answers the people there. In groups it only answers when it's mentioned or replied to. Other people get safe tools only, and approvals from a shared chat come to your DM. Palui stays your personal agent and never answers anyone else. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- An Agent bot (Telegram) connector gives an agent its own Telegram bot, so people can add it to a group and @mention it by name.
- Palui now reads WhatsApp groups. Nothing changes until you give a group an agent: messages there are ignored unless they mention Palui or reply to it.
- A Notes page and an Instructions & preferences skill. Palui can save standing instructions (always after your approval) and key-value defaults like `default_city`, and reads both at the start of every turn. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- A Remote MCP setup skill: ask Palui in chat to add a public MCP server (https, no auth) and it checks the URL, lists the tools and adds it after you approve. It can also list servers and remove the ones it added. See the Jadwal Sholat example in the docs.
- Palui can keep the important files you send in chat, like an ID card, a receipt or a ticket. Ask it in chat ("simpan KTP ini"), and the new Attachments page lists what it saved, with download and delete. It doesn't save everything you send, only files that matter or that you ask for. Files are encrypted with `MASTER_KEY` inside the database, capped at 10 MB, and limited to images, PDF, text and Office files. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- The chat header has a Copy menu: copy the whole conversation as Markdown (the newest 150 messages, with tool calls listed under each reply) or just the chat ID.
- Palui knows which chat it's in. Every turn now tells it the chat ID, the channel's own id (WhatsApp JID or Telegram chat id) and the current conversation ID, so "berapa chat id ini?" gets a real answer.
- A `thread_chat_ini` tool in the T3 Code connector lists the threads started or followed up from the current chat, with their ids and links. Thread results now also say which part of the link is the environment id (the same for every thread) and which is the thread id.
- A Chat history skill: ask Palui in a DM or the web chat to find another chat and read it ("cari chat grup keluarga terus rangkum obrolan terakhirnya"). `cari_chat` searches chats by title or id, and `baca_chat` reads up to 100 recent messages with optional time and text filters. Both are read-only and taint the turn, and they're never offered in a group or a webhook turn.
- A Routines skill: Palui builds recurring automations from chat out of generic parts. A time source (fixed times, a repeat rule, or times read daily from any read-only connector tool) plus an action (a message, a check-in with your own answer options that re-asks until you answer, or a prompt), with active days, pause until a date, and a daily or weekly recap. Answer a check-in with a button, by quoting it, or just by saying "udah". Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Each run on the Activity page and the Home runs card now opens its own page (`/app/activity/runs/<id>`). It shows the status, tokens (cached included), steps, model, the full error, the prompt, every tool call with its args and result, and the reply.

### Changed

- The persona moved from Settings to Palui's entry on the Agents page, and the Notes page edits instructions per agent. Your existing persona and instructions carry over to Palui.
- Each connector now opens on its own page (`/app/connectors/<id>`) instead of a side sheet, with a back link and the Save, Test and Connect buttons pinned at the bottom. Old `?open=<id>` links redirect there.
- The T3 Code setup asks for the pairing code first and shows the command to make one in a block with a Copy button. The text on its page is cut down to one short line per field, and the longer explanation lives in the docs.
- A connector that isn't set up yet opens with just the setup guide and the fields it needs. The optional settings sit behind a "More settings" link and show in full once it's connected. A step with a command now shows the command above the box you paste into.
- Every connector's setup now puts the guide above the field: where the value comes from first, then the box to paste it into. Telegram shows `/newbot` to send to @BotFather, CLIProxyAPI shows the command that prints its keys, and Google Calendar shows your real redirect URI with a Copy button before asking for the client ID.
- The rest of the dashboard got the same cut as T3 Code. Pages drop their subtitles, every connector page loses its long description, and field helpers, empty states and confirms are one short line. The how-it-works detail is in the docs, and the Google Calendar page there now has the OAuth client setup steps.

### Fixed

- Tools from an MCP server added last no longer vanish. A turn offered 30 tools at most, the skills took most of them, and a new server's tools were cut without a word while it still showed as on. The up-front limit is now 64, and anything past it loads through tool search (see Added).
- A connector page no longer stays on "Connecting" after the connector is already on. The status refreshes with the rest of the page every few seconds.
- Adding an MCP server shows Auth and Token right away instead of hiding them under "More settings". Header name shows only for the custom header mode, and Token only when the server needs one.
- Palui no longer re-checks your reminders, or any earlier work, on every message. Later turns now see the tool calls earlier turns made and their results, so it stops doubting its own replies and stops taking back answers that were right.
- Asking for the same thing again while an approval prompt still waits now drops the older request. You no longer get a late "that didn't run" message about something that was already answered.

## 0.3.0 (2026-11-11)

### Added

- Palui can run CLI commands on the Docker host through the new host bridge, a small MCP server you install with `ops/install-host-bridge.sh` and connect with the Host commands preset. Only commands you list in `~/.config/palui/host-bridge.json` run, with the values the model fills in checked against your patterns.
- The host bridge has an opt-in `dangerouslyAllowAnyCommand` setting that adds a `shell` tool for any command line. It's marked destructive, so every call asks first.

### Changed

- Add connector is now its own page (`/app/connectors/new`) instead of a dialog. The MCP server has its own section that separates Custom (any URL you set up yourself) from the presets, and each preset shows the host it connects to.

### Fixed

- The MCP tool table now lets you save tool classes you didn't change. Before, Save stayed disabled, so every tool from a new MCP server asked for approval as destructive. The "External server" switch moved up next to the tool table.

## 0.2.0 (2026-11-11)

### Added

- T3 Code connector: ask Palui in chat to work on one of your projects and it starts a T3 Code thread in its own worktree, then messages the same chat with the agent's reply and the link when the thread finishes. Set it up with a pairing code from `t3 auth pairing create`.

## 0.1.0 (2026-11-11)

The first tagged release. It covers everything built so far toward v1.

### Chat

- Telegram and WhatsApp DMs, plus the web chat in the dashboard, in Indonesian or English. WhatsApp runs on Palui's own number.
- One owner, claimed with a Telegram nonce link and a WhatsApp phone number.
- Durable inbox and outbox with at-least-once delivery, so a deploy doesn't drop a message.
- Sessions with compaction past about 40 messages.
- Chat commands: `/connectors`, `/new`, `/stop`, `/status`.
- Voice messages transcribed with ElevenLabs Scribe (Voice-in). Photos and small documents on Telegram.
- Pipe tables in replies render as tables in the web chat.

### Connectors

- Every capability is a connector of kind `channel`, `model`, `memory`, `tools` or `skill`.
- Pause, resume and remove from the dashboard, from chat or from the CLI, with no restart.
- A supervisor with isolated connectors and backoff (5 s, 30 s, 2 min, 10 min cap), and an alert after 5 minutes in `error`.

### Agent

- CLIProxyAPI and ai-gateway as model providers, with per-role failover.
- Pick each role's model from the list your gateway serves, or type any id it doesn't list, and set a reasoning effort per step in the chain.
- recall as long-term memory: tools, auto-recall, auto-save.
- Any Streamable HTTP MCP server as a tool source, with per-tool switches, classes and trust flags.
- Tool classes that fail closed, approvals that survive restarts, and the taint rule.
- A persona in Settings that shapes how Palui talks.
- Turn budgets (12 steps, 120 s, about 30 tools) and global caps.

### Skills

- Reminders in natural language, with RRULE recurrence, IANA zones, Done and Snooze, and delivery that survives restarts.
- Scheduled jobs, with a daily briefing and a heartbeat preset.
- Web fetch behind an SSRF guard.
- Inbound webhooks with HMAC signatures, in forward and summarize modes.
- Google Calendar, read-only.

### Dashboard

- Dashboard at `/app` with passkeys: Home, Chats, Reminders, Jobs, Connectors, Activity, Settings.
- No sign-up. The owner gets in with a single-use link from `palui owner invite` (15 minutes), which is also how you recover a lost passkey.
- Mono palette and the mascot head as the mark, matching the site.
- Page skeletons shaped like the real pages, and a progress bar while a page switch waits.
- Every page holds up on a phone and with very long names, big numbers and empty lists.

### Operations

- Docker Compose with two services from one image and one SQLite volume.
- `GET /health` reports the app version, and the runtime's version next to it.
- Pre-deploy snapshots, nightly age-encrypted backups to R2, and a restore drill.
- Landing page and these docs on Cloudflare Pages.

### Site

- A [brand page](/brand) with profile pictures for the bot's WhatsApp or Telegram account, in seven designs, dark and light, as PNG and SVG.
- The landing page describes Palui as a simple, friendly agent that keeps you company.

## Not in v1

These are planned for later and are not part of v1:

- Group chats. The code path exists, but the UI is hidden.
- Voice replies (text to speech). v1 has voice input only.
- stdio MCP servers, a shell tool and a browser tool. They need binaries in the container and a sandbox.
- Subagents.
- Self-written skills.
- Multiple profiles or agents.
- Multiple users.
- A native app.
