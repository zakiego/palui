Palui Agent uses [semantic versioning](https://semver.org). Each release is a git tag `vX.Y.Z` on `main`, and a running install reports its version as `version` in `GET /health`.

- While the version starts with `0.`, the v1 scope below is still being built. A minor bump (`0.2.0`) adds features or changes behavior. A patch bump (`0.1.1`) only fixes things.
- `1.0.0` is the release where the v1 scope is done. From then on, a major bump means you have to do something when you upgrade, and the release notes say what.
- Changes that need action from you on upgrade sit under "Breaking" in that release.

## 0.3.0 (2026-11-11)

### Added

- Palui can run CLI commands on the Docker host through the new host bridge, a small MCP server you install with `ops/install-host-bridge.sh` and connect with the Host commands preset. Only commands you list in `~/.config/palui/host-bridge.json` run, with the values the model fills in checked against your patterns.
- The host bridge has an opt-in `dangerouslyAllowAnyCommand` setting that adds a `shell` tool for any command line. It's marked destructive, so every call asks first.

### Changed

- Add connector is now its own page (`/app/connectors/new`) instead of a dialog. The MCP server has its own section that separates Custom (any URL you set up yourself) from the presets, and each preset shows the host it connects to.

### Fixed

- The MCP tool table now lets you save tool classes you didn't change. Before, Save stayed disabled, so every tool from a new MCP server asked for approval as destructive. The "External server" switch moved up next to the tool table.

## 0.2.0 (2026-11-11)

### Added

- T3 Code connector: ask Palui in chat to work on one of your projects and it starts a T3 Code thread in its own worktree, then messages the same chat with the agent's reply and the link when the thread finishes. Set it up with a pairing code from `t3 auth pairing create`.

## 0.1.0 (2026-11-11)

The first tagged release. It covers everything built so far toward v1.

### Chat

- Telegram and WhatsApp DMs, plus the web chat in the dashboard, in Indonesian or English. WhatsApp runs on Palui's own number.
- One owner, claimed with a Telegram nonce link and a WhatsApp phone number.
- Durable inbox and outbox with at-least-once delivery, so a deploy doesn't drop a message.
- Sessions with compaction past about 40 messages.
- Chat commands: `/connectors`, `/new`, `/stop`, `/status`.
- Voice messages transcribed with ElevenLabs Scribe (Voice-in). Photos and small documents on Telegram.
- Pipe tables in replies render as tables in the web chat.

### Connectors

- Every capability is a connector of kind `channel`, `model`, `memory`, `tools` or `skill`.
- Pause, resume and remove from the dashboard, from chat or from the CLI, with no restart.
- A supervisor with isolated connectors and backoff (5 s, 30 s, 2 min, 10 min cap), and an alert after 5 minutes in `error`.

### Agent

- CLIProxyAPI and ai-gateway as model providers, with per-role failover.
- Pick each role's model from the list your gateway serves, or type any id it doesn't list, and set a reasoning effort per step in the chain.
- recall as long-term memory: tools, auto-recall, auto-save.
- Any Streamable HTTP MCP server as a tool source, with per-tool switches, classes and trust flags.
- Tool classes that fail closed, approvals that survive restarts, and the taint rule.
- A persona in Settings that shapes how Palui talks.
- Turn budgets (12 steps, 120 s, about 30 tools) and global caps.

### Skills

- Reminders in natural language, with RRULE recurrence, IANA zones, Done and Snooze, and delivery that survives restarts.
- Scheduled jobs, with a daily briefing and a heartbeat preset.
- Web fetch behind an SSRF guard.
- Inbound webhooks with HMAC signatures, in forward and summarize modes.
- Google Calendar, read-only.

### Dashboard

- Dashboard at `/app` with passkeys: Home, Chats, Reminders, Jobs, Connectors, Activity, Settings.
- No sign-up. The owner gets in with a single-use link from `palui owner invite` (15 minutes), which is also how you recover a lost passkey.
- Mono palette and the mascot head as the mark, matching the site.
- Page skeletons shaped like the real pages, and a progress bar while a page switch waits.
- Every page holds up on a phone and with very long names, big numbers and empty lists.

### Operations

- Docker Compose with two services from one image and one SQLite volume.
- `GET /health` reports the app version, and the runtime's version next to it.
- Pre-deploy snapshots, nightly age-encrypted backups to R2, and a restore drill.
- Landing page and these docs on Cloudflare Pages.

### Site

- A [brand page](/brand) with profile pictures for the bot's WhatsApp or Telegram account, in seven designs, dark and light, as PNG and SVG.
- The landing page describes Palui as a simple, friendly agent that keeps you company.

## Not in v1

These are planned for later and are not part of v1:

- Group chats. The code path exists, but the UI is hidden.
- Voice replies (text to speech). v1 has voice input only.
- stdio MCP servers, a shell tool and a browser tool. They need binaries in the container and a sandbox.
- Subagents.
- Self-written skills.
- Multiple profiles or agents.
- Multiple users.
- A native app.
