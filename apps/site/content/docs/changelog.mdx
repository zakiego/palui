Palui Agent uses [semantic versioning](https://semver.org). Each release is a git tag `vX.Y.Z` on `main`, and a running install reports its version as `version` in `GET /health`.

- While the version starts with `0.`, the v1 scope below is still being built. A minor bump (`0.2.0`) adds features or changes behavior. A patch bump (`0.1.1`) only fixes things.
- `1.0.0` is the release where the v1 scope is done. From then on, a major bump means you have to do something when you upgrade, and the release notes say what.
- Changes that need action from you on upgrade sit under "Breaking" in that release.

## Unreleased

### Added

- An MCP server can be global or belong to one agent. On its connector page, "Who can use it" is Global (the default) or "One agent". Only the owner gets its tools, sees it in its capability list and can call it from a flow. Add the same server twice to give two agents different logins. On an agent's Tools tab each MCP server has a select for global or only this agent, and "Add MCP" adds one that agent owns. The Connectors page tags owned servers. Deleting an agent pauses the servers it owned. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Each agent's page is now split into sections you pick with big cards: Settings, Chats, Instructions, Memory and Tools. Chats shows where it answers, with the reply mode and "Answer here" for each. Memory shows its recall container, how many memories are in it and when it last saved. Tools lists every tool it can use by connector, marks MCP servers, says who can use them (you, you in groups, other people) and how often it ran each one this week.
- Groups have a reply mode: mentions only (the default) or every message. Set it with `/reply all` and `/reply mention` in the group, or with the new select on the Chats page. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Setting up a WhatsApp group no longer needs the dashboard. Mention Palui in a new group and it replies with your agents and the `/agent <slug>` to send. Before, every message in a group that wasn't allowed yet was dropped, `/agent` included.
- The Chats page marks chats whose "Answer here" is off as Off.

### Changed

- An agent's Tools tab is split into "Only this agent" and "Global", two cards you click between. Each server is one closed row with its tool count and how many are destructive, so the list fits on a screen. Open a row to see its tools. Changing a server's scope moves it to the other card. Searching opens every row with a match.
- Picking an agent for a chat, Palui included, turns the chat on. You no longer have to flip "Answer here" as well.
- In a group that has no agent, your own messages now need a mention like everyone else's, unless the group's reply mode is every message. That includes phrases meant for a flow's chat trigger; commands still work without one.
- In a WhatsApp group that's still off, only `/agent`, `/reply`, `/help` and `/id` run.
- Built-in tool names are English now, like `reminders__set_reminder`, `flows__list_flows`, `flows__recap` and `palui__search_tools` (they were Indonesian, like `ingatkan` and `daftar_flow`). Palui still answers in Indonesian. A flow you wrote by hand with an old built-in tool name fails its check until you update the step.

### Fixed

- WhatsApp and Telegram show their own logos in the dashboard and docs, not a speech bubble and a paper plane.
- A flow run with a chain of check-in reminders no longer shows as missed when you answered a later reminder. `flow_history` and recaps read the check-in that decided the run, and a late answer corrects that same one.

## 0.7.0 (2026-11-12)

### Breaking

- Routines are gone; flows do everything they did. The routine engine, the routine tools (`buat_rutinitas` and the rest), the Routines page, the `palui flows status` and `palui flows mode` commands and the old routine answer buttons are removed, and the app deletes the Routines connector on start. Routines that weren't handed over to flows stop firing, so if `palui flows status` on 0.6.0 still shows routines, run `palui flows mode flows` there and wait a minute before you upgrade. The routine tables stay for one more release, so rolling back to 0.6.0 still works.

### Added

- A flow check-in's deadline can now be computed. `{kind:"at", at:"{{steps.nextp.data.next.timestamp}}", plusMin:-10}` stops it 10 minutes before a time a tool returned, `{kind:"next", plusMin:-10}` stops it 10 minutes before the schedule's next occurrence, and `after` takes a template like `"{{vars.left}}"`. A deadline that has already passed skips the ask and takes `onMissed`, so a reminder chain like "last reminder 10 minutes before the next prayer" works whatever the gap between prayers is.
- Flow expressions get `choose(cond, a, b)`, which returns `a` when `cond` is true and `b` otherwise. "Remind at +70 minutes unless that's within 10 minutes of the last reminder" is now `choose(trigger.at + 70 * 60000 <= vars.last - 10 * 60000, trigger.at + 70 * 60000, vars.last)`.

### Changed

- The default turn time limit is now 5 minutes instead of 2. A slow model (Opus on high effort) spent 70 to 80 seconds on each step that wrote a flow draft, so a 2 minute turn fit one such step and then had to stop and say it ran out of time. An install that saved its budgets keeps its own value; change "Turn time limit" in Settings or ask Palui to.
- A flow run can send 10 messages instead of 5. A prayer check-in chain (the ask, reminders at +10, +30, +70 and +150 minutes, and a last one before the next prayer) is six asks, and the Zuhur and Isya runs failed with "More than 5 messages in one run". Re-asks and missed notes still don't count.
- The newest call of each tool keeps its arguments in the history up to 32,000 characters, so the next turn sees the flow draft it wrote last time instead of "arguments left out of the history" and fixes it rather than rebuilding it. Older large calls are still left out.
- A flow id or set value name that breaks the naming rule now gets a problem that quotes the name (`"Init": Ids use lowercase letters...`, `Key "L": Variable names use...`) instead of "Invalid key in record", and buat_flow spells the rule out.
- A flow's page now draws its steps as a graph: triggers on top, each step as a card, branches as labelled arrows, and an "ends" mark wherever a run can finish. Click a step to read it in full under the graph.

### Fixed

- A turn that runs out of time no longer ends in silence. When the next step probably won't fit in the time left, or it's the last allowed step, the model is told to answer now with no tools. If a turn still times out, the chat gets a short note saying what ran, whether anything changed, and to say "lanjut" to continue, and the next turn sees that note too.
- On the Flows page, clicking anywhere on a flow's row now opens it. Before, only the flow's name was a link, so most of the row did nothing.

## 0.6.0 (2026-11-12)

### Added

- Palui can read its own setup and change its settings from chat. Ask "timezone kamu apa?" or "ganti model fast ke claude-haiku-4-5" and the new builtin Settings connector looks up or changes the timezone, language, model roles, budgets and fallback channel. Every change asks you first, only Palui (not other agents) can make one, and secrets are never shown.
- `/report` in any chat replies with a debug snapshot of that chat: chat and session ids, recent runs with every tool call they made and the approvals behind them, the last 10 messages, unsent outbox rows, recent warnings and state changes (flows, routines, approvals, reminders), what the chat has scheduled right now, where the database lives and a dashboard link. It stays within one WhatsApp or Telegram message and says what it left out. Add a note after it (`/report it answered twice`) and paste the reply into a coding agent; sent without a note, the reply asks for one next time. Each report gets an id (`rpt_...`) and is saved in the database, so the id alone is enough later. In a group the report goes to your own chat and the group only sees the id. A flow can no longer use `/report` as its chat trigger. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Eight new chat commands. `/help` lists the commands, including the ones your flows answer to. `/usage` shows today's tokens and runs by model and agent. `/models` lists what each model connector offers, and `/model <name>` puts a model first for a role (the same setting as the dashboard's Settings page). `/tools` shows the tools a turn in this chat would get. `/btw <question>` answers a side question without adding it to the session. `/compact` folds the older messages into the session summary now. `/id` shows the chat, session and message ids, and the ids of a message you quote.
- Ask Palui to turn a routine into a flow and it keeps the routine's schedule, pause state, open check-ins and whole log (the new `jadikan_flow` routine tool). Before, replacing a routine meant deleting it, and its history and shadow flow went with it. Deleting a routine now says plainly that its log goes too.

### Changed

- `/help`, `/models`, `/model`, `/usage`, `/btw`, `/compact`, `/tools` and `/id` are now built-in commands, so a flow can't use them as its chat command. A flow that already does stops answering to it: give it another command.

### Fixed

- On WhatsApp, "typing…" no longer flashes for a split second and disappears before the ⏳ reaction. The reaction now goes first and typing starts about 1.5 seconds later, and a reply that comes faster than that skips typing altogether.
- After you approve a tool, Palui no longer trusts lists it read in the same step before your answer. It used to say a delete hadn't worked because a list taken a second earlier still showed the item.
- A routine's shadow flow no longer blocks a flow you create with the same name. Shadow flows are now hidden from every flow tool, not only the list, and the shadow one moves aside to `<name> (rutinitas)`.
- Checking a draft flow now finds the recap tool (`flows__ringkasan`) for a recap step, and a re-ask that uses the routine-style `{{n}}` points to `{{run.followUps}}`.

## 0.5.0 (2026-11-12)

### Added

- A Routines page in the dashboard lists every routine across your chats with its schedule, next time, action, recap and anything that needs a look: a failing source, a source connector that's missing or off, or a check-in waiting for an answer. Open one to see it drawn as the steps it runs (when, ask or send, what happens with no answer, recap), its next times, done per item, and its log with counts per status, filtered by date. You can pause, pause until a time, resume or delete it there; creating and editing stays in chat.
- Each agent now has its own page (`/app/agents/<slug>`), opened from its row on the Agents page. It holds the profile, the shared-chat rules, the daily cap with today's usage, the recall container, its standing instructions (add, edit, switch off and delete them right there) and the chats it answers in, each with its Answer here switch. New agent asks only for a name, slug and persona, then opens that page.
- Flows: automations Palui builds from chat out of triggers and steps. A flow starts on a schedule, a webhook, a chat command or phrase, a value that changes, another flow's check-in or run, or by hand, and its steps call tools, branch on conditions, set variables, send messages, ask check-ins, wait, run a prompt, or repeat for each item in a list. Nothing calls the model unless a prompt step asks, and every run is logged step by step, skips included. Ask in chat; Palui checks and dry-runs a flow before saving it, and `kenapa_flow` explains why one didn't run. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Write tools in a flow are approved once per flow version. A run still asks when an argument comes from outside data, when a tool's class changed, or when the tool is set to ask every run (the new "In flows, ask" setting on an MCP server's tool list). Destructive tools never run in a flow.
- A read-only Flows page in the dashboard lists every flow with its next time and last run. A flow's page shows its steps and branches, versions and recent runs, and a flow run opens its step log on the run page.
- Webhooks get a third mode, `flow`: the body starts the flows listening to that hook, deduped by the `x-palui-delivery` or `X-GitHub-Delivery` header. Saving a flow with a webhook trigger switches its hook to this mode.
- `palui__cari_tool` results now say each tool's class and whether its output is untrusted.

### Changed

- Routines are moving to flows. After this upgrade each routine also gets a flow that runs in shadow: it computes the same times but sends nothing, and differences are logged (the Flows page and `palui flows status` show the count). The routine engine keeps sending until you run `palui flows mode flows`, which hands over with open check-ins and old buttons intact; `palui flows mode legacy` goes back. After the handover the routine tools edit flows, and the Routines page links each routine to its flow and pauses or deletes the flow along with it.
- Prompt caching now works between turns, not only inside one. The clock, recall and check-ins moved out of the system prompt to the end of your newest message, so the model can reuse the tools, the system prompt and the earlier conversation it already read. Against CLIProxyAPI, a follow-up turn read 98% of its input from the cache where it read none before.
- Tokens read from the prompt cache now count at 10% against the global, agent, job and flow daily caps, about what they cost next to fresh input. Fresh input, cache writes and output still count in full, and `/status` shows the weighted number. On 2026-11-11 the old count paused turns at 2.03M tokens when about 0.8M was real cost.
- A run's page (Activity) shows input read from the cache and input written to it separately, plus what the run counted toward the caps. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- The global daily token cap (Settings, Limits) can now be set to 0 to turn it off, the same as an agent's or a job's cap, so turns never pause on token use. `/status` shows `tanpa batas` when it's off.

### Fixed

- Raising the daily token cap or runs per hour (or setting the token cap to 0) now lifts a budget pause on the next message instead of at midnight, and `/status` shows the cap that applies now. Before, a pause stayed until midnight even after you raised the cap, and turns could fail once that pause ran out.

## 0.4.0 (2026-11-11)

### Added

- Tool search. When more tools are enabled than Tools per turn (Settings, Limits), Palui loads a core set and lists the rest by name. It finds what it needs with `palui__cari_tool` (keywords in any language or exact names), calls it in the same turn, and keeps it loaded for the rest of the conversation. However many skills and MCP servers you add, none of their tools get dropped. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Agents: named personas with their own instructions, recall memory, daily token cap and avatar (an uploaded photo, or an icon and a color). Give one to a WhatsApp or Telegram group, or to someone else's DM, from the new Agents and Chats pages or with `/agent <slug>`, and it answers the people there. In groups it only answers when it's mentioned or replied to. Other people get safe tools only, and approvals from a shared chat come to your DM. Palui stays your personal agent and never answers anyone else. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- An Agent bot (Telegram) connector gives an agent its own Telegram bot, so people can add it to a group and @mention it by name.
- Palui now reads WhatsApp groups. Nothing changes until you give a group an agent: messages there are ignored unless they mention Palui or reply to it.
- A Notes page and an Instructions & preferences skill. Palui can save standing instructions (always after your approval) and key-value defaults like `default_city`, and reads both at the start of every turn. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- A Remote MCP setup skill: ask Palui in chat to add a public MCP server (https, no auth) and it checks the URL, lists the tools and adds it after you approve. It can also list servers and remove the ones it added. See the Jadwal Sholat example in the docs.
- Palui can keep the important files you send in chat, like an ID card, a receipt or a ticket. Ask it in chat ("simpan KTP ini"), and the new Attachments page lists what it saved, with download and delete. It doesn't save everything you send, only files that matter or that you ask for. Files are encrypted with `MASTER_KEY` inside the database, capped at 10 MB, and limited to images, PDF, text and Office files. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- The chat header has a Copy menu: copy the whole conversation as Markdown (the newest 150 messages, with tool calls listed under each reply) or just the chat ID.
- Palui knows which chat it's in. Every turn now tells it the chat ID, the channel's own id (WhatsApp JID or Telegram chat id) and the current conversation ID, so "berapa chat id ini?" gets a real answer.
- A `thread_chat_ini` tool in the T3 Code connector lists the threads started or followed up from the current chat, with their ids and links. Thread results now also say which part of the link is the environment id (the same for every thread) and which is the thread id.
- A Chat history skill: ask Palui in a DM or the web chat to find another chat and read it ("cari chat grup keluarga terus rangkum obrolan terakhirnya"). `cari_chat` searches chats by title or id, and `baca_chat` reads up to 100 recent messages with optional time and text filters. Both are read-only and taint the turn, and they're never offered in a group or a webhook turn.
- A Routines skill: Palui builds recurring automations from chat out of generic parts. A time source (fixed times, a repeat rule, or times read daily from any read-only connector tool) plus an action (a message, a check-in with your own answer options that re-asks until you answer, or a prompt), with active days, pause until a date, and a daily or weekly recap. Answer a check-in with a button, by quoting it, or just by saying "udah". Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Each run on the Activity page and the Home runs card now opens its own page (`/app/activity/runs/<id>`). It shows the status, tokens (cached included), steps, model, the full error, the prompt, every tool call with its args and result, and the reply.

### Changed

- The persona moved from Settings to Palui's entry on the Agents page, and the Notes page edits instructions per agent. Your existing persona and instructions carry over to Palui.
- Each connector now opens on its own page (`/app/connectors/<id>`) instead of a side sheet, with a back link and the Save, Test and Connect buttons pinned at the bottom. Old `?open=<id>` links redirect there.
- The T3 Code setup asks for the pairing code first and shows the command to make one in a block with a Copy button. The text on its page is cut down to one short line per field, and the longer explanation lives in the docs.
- A connector that isn't set up yet opens with just the setup guide and the fields it needs. The optional settings sit behind a "More settings" link and show in full once it's connected. A step with a command now shows the command above the box you paste into.
- Every connector's setup now puts the guide above the field: where the value comes from first, then the box to paste it into. Telegram shows `/newbot` to send to @BotFather, CLIProxyAPI shows the command that prints its keys, and Google Calendar shows your real redirect URI with a Copy button before asking for the client ID.
- The rest of the dashboard got the same cut as T3 Code. Pages drop their subtitles, every connector page loses its long description, and field helpers, empty states and confirms are one short line. The how-it-works detail is in the docs, and the Google Calendar page there now has the OAuth client setup steps.

### Fixed

- Tools from an MCP server added last no longer vanish. A turn offered 30 tools at most, the skills took most of them, and a new server's tools were cut without a word while it still showed as on. The up-front limit is now 64, and anything past it loads through tool search (see Added).
- A connector page no longer stays on "Connecting" after the connector is already on. The status refreshes with the rest of the page every few seconds.
- Adding an MCP server shows Auth and Token right away instead of hiding them under "More settings". Header name shows only for the custom header mode, and Token only when the server needs one.
- Palui no longer re-checks your reminders, or any earlier work, on every message. Later turns now see the tool calls earlier turns made and their results, so it stops doubting its own replies and stops taking back answers that were right.
- Asking for the same thing again while an approval prompt still waits now drops the older request. You no longer get a late "that didn't run" message about something that was already answered.

## 0.3.0 (2026-11-11)

### Added

- Palui can run CLI commands on the Docker host through the new host bridge, a small MCP server you install with `ops/install-host-bridge.sh` and connect with the Host commands preset. Only commands you list in `~/.config/palui/host-bridge.json` run, with the values the model fills in checked against your patterns.
- The host bridge has an opt-in `dangerouslyAllowAnyCommand` setting that adds a `shell` tool for any command line. It's marked destructive, so every call asks first.

### Changed

- Add connector is now its own page (`/app/connectors/new`) instead of a dialog. The MCP server has its own section that separates Custom (any URL you set up yourself) from the presets, and each preset shows the host it connects to.

### Fixed

- The MCP tool table now lets you save tool classes you didn't change. Before, Save stayed disabled, so every tool from a new MCP server asked for approval as destructive. The "External server" switch moved up next to the tool table.

## 0.2.0 (2026-11-11)

### Added

- T3 Code connector: ask Palui in chat to work on one of your projects and it starts a T3 Code thread in its own worktree, then messages the same chat with the agent's reply and the link when the thread finishes. Set it up with a pairing code from `t3 auth pairing create`.

## 0.1.0 (2026-11-11)

The first tagged release. It covers everything built so far toward v1.

### Chat

- Telegram and WhatsApp DMs, plus the web chat in the dashboard, in Indonesian or English. WhatsApp runs on Palui's own number.
- One owner, claimed with a Telegram nonce link and a WhatsApp phone number.
- Durable inbox and outbox with at-least-once delivery, so a deploy doesn't drop a message.
- Sessions with compaction past about 40 messages.
- Chat commands: `/connectors`, `/new`, `/stop`, `/status`.
- Voice messages transcribed with ElevenLabs Scribe (Voice-in). Photos and small documents on Telegram.
- Pipe tables in replies render as tables in the web chat.

### Connectors

- Every capability is a connector of kind `channel`, `model`, `memory`, `tools` or `skill`.
- Pause, resume and remove from the dashboard, from chat or from the CLI, with no restart.
- A supervisor with isolated connectors and backoff (5 s, 30 s, 2 min, 10 min cap), and an alert after 5 minutes in `error`.

### Agent

- CLIProxyAPI and ai-gateway as model providers, with per-role failover.
- Pick each role's model from the list your gateway serves, or type any id it doesn't list, and set a reasoning effort per step in the chain.
- recall as long-term memory: tools, auto-recall, auto-save.
- Any Streamable HTTP MCP server as a tool source, with per-tool switches, classes and trust flags.
- Tool classes that fail closed, approvals that survive restarts, and the taint rule.
- A persona in Settings that shapes how Palui talks.
- Turn budgets (12 steps, 120 s, about 30 tools) and global caps.

### Skills

- Reminders in natural language, with RRULE recurrence, IANA zones, Done and Snooze, and delivery that survives restarts.
- Scheduled jobs, with a daily briefing and a heartbeat preset.
- Web fetch behind an SSRF guard.
- Inbound webhooks with HMAC signatures, in forward and summarize modes.
- Google Calendar, read-only.

### Dashboard

- Dashboard at `/app` with passkeys: Home, Chats, Reminders, Jobs, Connectors, Activity, Settings.
- No sign-up. The owner gets in with a single-use link from `palui owner invite` (15 minutes), which is also how you recover a lost passkey.
- Mono palette and the mascot head as the mark, matching the site.
- Page skeletons shaped like the real pages, and a progress bar while a page switch waits.
- Every page holds up on a phone and with very long names, big numbers and empty lists.

### Operations

- Docker Compose with two services from one image and one SQLite volume.
- `GET /health` reports the app version, and the runtime's version next to it.
- Pre-deploy snapshots, nightly age-encrypted backups to R2, and a restore drill.
- Landing page and these docs on Cloudflare Pages.

### Site

- A [brand page](/brand) with profile pictures for the bot's WhatsApp or Telegram account, in seven designs, dark and light, as PNG and SVG.
- The landing page describes Palui as a simple, friendly agent that keeps you company.

## Not in v1

These are planned for later and are not part of v1:

- Group chats. The code path exists, but the UI is hidden.
- Voice replies (text to speech). v1 has voice input only.
- stdio MCP servers, a shell tool and a browser tool. They need binaries in the container and a sandbox.
- Subagents.
- Self-written skills.
- Multiple profiles or agents.
- Multiple users.
- A native app.
