description: Every Palui Agent release, newest first, and what is planned after v1.
---

Palui Agent uses [semantic versioning](https://semver.org). Each release is a git tag `vX.Y.Z` on `main`, and a running install reports its version as `version` in `GET /health`.

- While the version starts with `0.`, the v1 scope below is still being built. A minor bump (`0.2.0`) adds features or changes behavior. A patch bump (`0.1.1`) only fixes things.
- `1.0.0` is the release where the v1 scope is done. From then on, a major bump means you have to do something when you upgrade, and the release notes say what.
- Changes that need action from you on upgrade sit under "Breaking" in that release.

## Unreleased

Nothing yet.

## 0.10.0 (2026-11-18)

### Added

- Save your own chat commands on the dashboard. The new Commands page stores a prompt under a `/name`, for every agent or for one agent, and typing it runs a normal turn with that prompt. `{{args}}` takes the text typed after the command, and "Attach a debug report" adds the `/report` snapshot, so a command like `/report-fix` can hand a bug straight to a T3 Code thread. Your commands show up in `/help`, and four new MCP tools manage them. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Manage Palui from your own AI agents. Palui now serves an MCP server at `/mcp` with 74 tools that do what the dashboard does: settings, agents, chats, connectors, notes, jobs, flows, reminders, outbound and attachments. Apps that only take a URL connect with OAuth and a consent page in the dashboard; agents in a terminal use a personal token from Settings → Security → MCP access, or `palui mcp token <name>` on the server. Both are listed with when they were last used and can be revoked there. Adds a migration; rolling back past this release needs the pre-deploy snapshot. The edge Worker needs a redeploy so `/mcp` and the OAuth discovery documents reach the app.
- An agent's Tools tab now says whose data each tool touches: "Data: per chat", "Data: this agent" or "Data: all agents", next to the tool count. Use it to check what an agent in a friends' group can reach. A server you switch between Only this agent and Global changes its label with it.
- Agents can search the web. Web fetch gets a `search_web` tool that returns the top results (title, link and snippet) for a query, so an agent finds the right page before reading it instead of guessing URLs. Guests in a group can use it too, like `fetch_page`.
- An agent's Tools tab now says who gets each tool: "Everyone in the chat", "You and members", "Only you" or "Off". A closed server row says the same for the whole server, with a count when only some of its tools reach that far.
- MCP servers get a "Holds no private data" switch on an agent's Tools tab, for a server that keeps nothing about you, like prayer times. Once it's on, that server's tools that aren't destructive reach groups and other people's DMs and run there without asking. On a global server it applies to every agent. Changing the server's URL turns it off again.
- Agents can have members. On an agent's page, add the people you trust with it (a name plus their WhatsApp number or Telegram id, picked from people who already wrote or typed in). A DM with a member, or a WhatsApp group where everyone is you or a member, also gets that agent's own tools: its MCP servers, notes, contacts and memory, with no approval prompts and never anything destructive. A group with anyone else in it stays as before, and so does every Telegram group, because a bot can't see who's in one. A member of one agent is a stranger to the others, and Palui has no members. Adds a migration; rolling back past this release needs the pre-deploy snapshot.

- Ask Palui about your other agents. In your own DM or the web chat, Palui can list the chats your other agents answer in, read them (who wrote each message, paged 30 at a time), and search or list those agents' memory, so "what did the book club group say today?" just works. Anyone in those chats can write something for Palui to read, so after reading them every write asks you first, even a tool you set to allow, and the next turns ask too while what Palui read is in the conversation. No other agent can read Palui's chats or your memory, and groups, webhooks and flows never get these tools.

### Changed

- A tool result stays untrusted on the next turns. Palui shows past tool results to the model again, so in a turn whose history holds a web page, an `external` MCP result or another chat it read, writes now ask you first. Before, only the turn that read it did. Auto-save still keeps those later turns.

- A group no longer sees your list of agents. When you mention the bot in a WhatsApp group that has no agent yet, or type `/agent` in any group or someone else's DM, the chat only hears that no agent is set up, and the `/agent <name>` choices go to your own DM. `/usage` in a group only shows that group's agent.

- In a group, an agent now reads the whole conversation but still only answers when it's @mentioned or replied to. Before, it only ever saw the messages addressed to it, so "@agent what do you think?" came with no idea what was being discussed. The talk around a mention is kept as context and is never answered on its own. It also tells people plainly what it can read.

- An agent now sees the photos, files and voice notes guests send it, not only yours. Before, a guest's photo in a group or DM set up with an agent reached it as text only, and a photo with no caption didn't reach it at all, so it told them it couldn't see what they sent. A photo in the group's talk around a mention still shows only as a placeholder; send it with the message that mentions the agent. When a photo can't be downloaded, the agent is told so instead of getting nothing.

- Voice notes from guests aren't transcribed, so they don't add to your transcription bill. The agent gets a note that a voice note came in and asks them to type it. Your own voice notes are transcribed as before.

- Agents in groups and in other people's DMs now get reminders, saved files, web search and web fetch for everyone in that chat, with no approval prompts. They never get destructive tools or anything that reaches your notes, contacts, memory, jobs, accounts or MCP servers, and can't find out those exist. Your own message in a group gets the same set, Palui's groups included, and a tool you set to "Ask first" or "Off" isn't offered there. The "When you write there" setting on the agent sheet is gone, and the Tools tab marks each tool a shared chat gets. A scheduled job that posts into a group keeps only those tools.

- The agents API and the `get_agent` and `save_agent` MCP tools no longer have `ownerPowers`. It did nothing since groups stopped asking for approval. An AI agent or script that still sends it keeps working, and the value is ignored. The unused `owner_powers` column stays in the database for now; a later release drops it.

### Fixed

- Agents can see WhatsApp stickers. Before, a sticker with no text never reached the agent at all. Now it arrives as an image marked as a sticker, so the agent can react to it, and an animated sticker comes through as its first frame. It follows the same rules as photos: a guest's sticker is only read when it's part of a message the agent will answer.
- A flow whose schedule takes its times from a tool (like prayer times from an external MCP server) no longer asks for approval on every write once its version is approved. The tool only hands back times, so the scheduled time, date and item label aren't treated as outside data anymore. A list source that copies labels from the tool still asks.
- In a group, an agent no longer tells people a tool is "not open right now" and to try again later. It used to list every connector as available even when the group couldn't use them, so it promised things like reminders it had no tool for. Now it only names what that chat can actually use and says plainly when it can't do something there.
- In groups and other people's DMs, the tool search and the agent's instructions no longer mention flows, destructive tools or approvals, so the agent stops hinting at things that chat can't have.
- Agents keep to their own jobs, MCP servers and connectors. `list_jobs` now lists only the jobs that post into the asking agent's chats, so an agent in a friends' group can't read your briefings. An MCP server added from a chat with any agent but the default belongs to that agent, and that agent can't remove a server every agent uses. `get_settings` lists only the connectors the agent can call.

## 0.9.0 (2026-11-15)

### Breaking

- Palui now runs as one service instead of two. The server, the channels, agent turns, the scheduler and the dashboard are a single program, so `compose.yaml` has only `app`, and the image is about 42 MB instead of 399 MB. On the same test database, idle memory went from about 153 MB for the two old containers to about 11 MB. Your database, connectors, chats and settings carry over as they are. After you upgrade: sign in to the dashboard again (old sessions end; your passkey still works, and `docker compose exec app palui owner invite` gets you in if it doesn't), and pair WhatsApp again from its connector page, since the WhatsApp session is stored in a new format under `/data/wa/`. Once WhatsApp works, you can delete the old session with `docker compose exec app rm -r /data/wa-auth`. `BETTER_AUTH_SECRET`, `RUNTIME_URL` and `CONTROL_PORT` are no longer read, so you can remove them from `.env`; keep `MASTER_KEY` and `APP_URL`. `scripts/pre-deploy.sh` removes the old `runtime` container on the first deploy. `APP_URL` should use a host name: with an IP address the server still starts, but passkeys are off and the log says why. The nightly backup now uploads WhatsApp as `wa-<timestamp>.tar.age`.

### Added

- Add a contact from chat. Ask Palui to add a contact with a name and a phone number, and it shows you the name and the cleaned-up number to approve before it's saved to that agent's contacts. It always asks, even when the agent may run every tool without asking. New contacts start at Always ask, and only the Outbound page can switch one to Always allow. A number that's already saved comes back as the existing contact instead of a duplicate. Flows, webhooks and guests can't add contacts.
- Pick the reaction per WhatsApp chat. Palui puts ⏳ on your message while it writes a reply, and now each chat can turn that off or use another emoji. Send `/ack off`, `/ack on` or `/ack 👀` in the chat, or pick it under "Reaction" on the Chats page or an agent's Chats tab. Typing still shows when it's off. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Palui can delete a saved document from recall with `forget_document`, so the full text of a note it saved stops showing up in searches. Before, it could only forget the facts taken from a document, and the text itself had to be deleted on the recall dashboard. It asks you first and only touches the agent's own container.
- Agents can keep a separate memory per chat. On an agent's Memory tab, "Separate memory per chat" gives each chat its own recall container, so what one customer said never comes up in another customer's chat. New agents start with it on; existing ones keep their single container until you turn it on. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Shared containers on an agent's Memory tab: up to 5 recall containers it reads but never writes, like a `kb-shop` you fill with product facts. Auto-recall shows them next to the agent's own memory, labeled as reference only. Palui can use them too.
- Activity > Usage splits tokens per agent. A new "Per agent" card next to Per model shows each agent's tokens and runs over the last 14 days. Runs from before agents count toward Palui, and runs of a deleted agent group under "Deleted agent".

### Fixed

- Another agent can no longer pick your memory as its own or shared container when the recall connector has no container picked. Before, the check assumed your memory was called `default`, while recall actually used its own default (like `zaki`), so an agent's Memory tab accepted `zaki`. Palui now asks recall for that name, keeps it in the connector's config, and refuses it on every agent but Palui.
- `forget_memory` and `forget_document` work again when the recall connector has no container picked. Before, a fact or document Palui had just saved answered "No memory with that id", because add and search used recall's default container while forget compared against an empty name. Palui now asks recall which container its default is and uses that one name for every recall tool. Auto-recall in that setup also reads your real memory again instead of an empty container named `undefined`, and the "can't use recall container" error names the containers the agent may use.
- Palui can no longer read or write another agent's memory. Before, only agents other than Palui were locked to their own recall containers, so Palui could search or save into, say, `agent-finansial`. Now Palui reaches your memory plus the shared containers on its Memory tab, and nothing else. Add an agent's container to Palui's shared list if you want Palui to read it. Flow steps and tool sources now run with their flow agent's memory limits too; before, they weren't limited at all. Recall's `purge_container` and any recall tool Palui doesn't know yet are no longer offered.
- An agent's chat history tools only reach the chats it answers in. Before, `search_chats` listed every chat and `read_chat` read any of them, so Palui in your DM could read the group another agent serves and save it to its memory. Now another agent's chat doesn't show up in a search, and reading it by id or JID returns an error with nothing from the chat. The dashboard still shows every chat.
- An agent other than Palui can no longer read or change your memory through recall's tools. Before, its `search_memories` and `add_memory` defaulted to Palui's container and took any container the model named, so a question from you in a group could pull your private facts into that group. Its tools now reach only its own container and its shared ones, `forget_memory` checks the memory's container first, and recall tools Palui doesn't know yet (like `upcoming`, which can read every container) are left out. Agents also can't pick your container as their own or as a shared one.
- A photo or document you sent a few messages ago can still be saved. Before, `save_attachment` only took files from the message being answered, so when the agent showed a transaction preview first and you said "ya" later, the receipt couldn't be saved or attached anymore and the agent asked you to send it again. Now it can pick a file from this chat's last 24 hours (`earlier: true`), matched by caption and time.

### Changed

- Every message to a contact now ends with a signature, added by Palui itself instead of the agent remembering an instruction. It covers messages sent now, scheduled and repeating ones, and flow message steps with `contact`, and it sits after the text with one blank line between. The approval and the 15-second cancel notice show it, so you approve exactly what goes out. The default says the message is automatic and replies to that number aren't read. Turn it off or edit it under "Limits and signature" on the Outbound page. To send one message without it, ask for that in chat (`send_message` takes `signature: false`, and a flow message step can set it too). A text that already ends with the signature, or with one of the earlier texts, isn't signed twice. The body limit stays at 1800 characters and the signature can be up to 150, so the total always fits the 2000 character cap. You can delete the standing instruction that added the signature by hand.
- The Messages to contacts tools have English names now: `outbound__send_message`, `outbound__cancel_message`, `outbound__list_contacts` and `outbound__list_outbound_messages` (they were `kirim_pesan`, `batal_pesan`, `daftar_kontak` and `daftar_pesan_keluar`). Palui still answers in Indonesian. If you set a per-tool permission for one of the old names on an agent's Tools tab, set it again.
- The landing page at palui.zakiego.com is redesigned. Asks type themselves in above Palui, which acts each one out, and seven boxes below show what it does as live demos: chatting, asking before it acts, remembering, reminders, connectors, scheduled jobs and the install commands. It stands still when your system asks for reduced motion.
- The landing page now matches the dashboard: Inter instead of IBM Plex, the dashboard's dark neutrals and corner radii, an indigo focus ring, and demos that show a finished step as a green check and a connector that's on as an indigo switch. The share card for links to the site has the same look.
- Forgetting several memories asks you once. `forget_memory` takes up to 20 ids in one call, so cleaning up a batch of facts is one "ya" instead of one prompt per fact.
- The new version notice also goes out when a deploy runs a new commit on the same version. It names the new and old short commit and lists up to 8 commit titles in between, like "Palui di-update ke commit abc1234 (sebelumnya def5678), versi 0.8.0". A version bump adds the short commit to the usual message. A restart on the same commit still sends nothing, and a build that doesn't know its commit (a local `docker build`) falls back to the version alone. The deploy's `scripts/pre-deploy.sh` writes the commit into `build-info.json`, which the image carries.
- The dashboard has a new, quieter look: near-black panels at night, Inter type, compact pill buttons, hairline cards and an indigo switch for "on". The header is shorter, the sidebar drops its tagline, the command palette opens near the top, Settings and Activity switch sections with line tabs, every status shows an icon next to its word, model logos are drawn in plain black or white, and helper text is one short line. Pages, data and controls work the same as before.
- The docs at palui.zakiego.com/docs match the dashboard: Inter and Geist Mono, the dashboard's neutrals in both themes, quieter callouts and tables, code blocks without a card look, and a search box that opens at once.
- Placeholders like `{{trigger.label}}` stand out on a flow's graph. In a step's card, the trigger pill and the step detail, each `{{...}}` shows as a small mono chip, so `🕌 {{trigger.label}}` reads as a fixed emoji plus a value filled in at run time.

## 0.8.0 (2026-11-13)

### Added

- Saved attachments can be previewed and shared. On the Attachments page, click a file's title or the eye icon to see an image, PDF or text file, or open it in a new tab. The link icon makes a temporary link: public for anyone who has it, or private so it only opens when you're signed in, for 1 hour, 24 hours or 7 days. Each file lists its live links, how often they were opened, and a button to turn one off. The agent can do the same with the new `share_attachment` and `unshare_attachment` tools, so asking for your KTP gets you a link that opens the file itself. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Tool permissions per agent. On an agent's Tools tab, "Allow every tool without asking" stops the approval prompts for your own messages, and each tool has a select: Default, Allow, Ask first or Off. Off hides the tool from that agent. Jobs, flows, hooks and other people keep the usual rules. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- An MCP server can be global or belong to one agent. On its connector page, "Who can use it" is Global (the default) or "One agent". Only the owner gets its tools, sees it in its capability list and can call it from a flow. Add the same server twice to give two agents different logins. On an agent's Tools tab each MCP server has a select for global or only this agent, and "Add MCP" adds one that agent owns. The Connectors page tags owned servers. Deleting an agent pauses the servers it owned. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Each agent's page is now split into tabs: Settings, Chats, Instructions, Memory and Tools. Chats shows where it answers, with the reply mode and "Answer here" for each. Memory shows its recall container, how many memories are in it and when it last saved. Tools lists every tool it can use by connector, marks MCP servers, says who can use them (you, you in groups, other people) and how often it ran each one this week.
- Groups have a reply mode: mentions only (the default) or every message. Set it with `/reply all` and `/reply mention` in the group, or with the new select on the Chats page. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Setting up a WhatsApp group no longer needs the dashboard. Mention Palui in a new group and it replies with your agents and the `/agent <slug>` to send. Before, every message in a group that wasn't allowed yet was dropped, `/agent` included.
- The Chats page marks chats whose "Answer here" is off as Off.
- You can answer a flow check-in before it asks. While a run is still waiting before its check-in (like the 10 minutes after "Waktu Ashar sudah masuk"), "udah" is kept, and when the run gets there it skips the question and its reminders and follows that answer's branch. Only a closing answer counts early; a "belum" still waits for the question.
- Palui can tell you when a new version is running. It's off by default. On an agent's Chats tab, turn on "New version notice" for the chats you want it in. After a deploy each of them gets one message, from the bot that answers there, with the new and old version and a link to the changelog. A restart on the same version, or a fresh install, sends nothing.
- The agent knows the dashboard's pages. Ask it where to add a connector, change the model or set up a webhook and it replies with the full link, like `/app/connectors/new` or `/app/settings?tab=models`, built from `APP_URL`. Only in your own chats, never in shared ones.

### Changed

- Home shows what needs attention first: a connector with an error, or one that's on but paused, sits at the top with its reason and a link to fix it. Tokens today has a bar for each of the last 7 days, the next reminders read like an agenda with the time first, and on a phone the connector map moves to the bottom.
- Switching pages in the dashboard is close to instant. Every sidebar page loads in the background once you're in, and a page you've already seen shows right away and refreshes behind it. Before, each switch waited on the server twice.
- A flow's page is split into Steps, Runs and Versions tabs, and lines up at one width with its header.
- An agent's Tools tab is split into "Only this agent" and "Global", two cards you click between. Each server is one closed row with its tool count and how many are destructive, so the list fits on a screen. Open a row to see its tools. Changing a server's scope moves it to the other card. Searching opens every row with a match.
- Picking an agent for a chat, Palui included, turns the chat on. You no longer have to flip "Answer here" as well.
- In a group that has no agent, your own messages now need a mention like everyone else's, unless the group's reply mode is every message. That includes phrases meant for a flow's chat trigger; commands still work without one.
- In a WhatsApp group that's still off, only `/agent`, `/reply`, `/help` and `/id` run.
- Built-in tool names are English now, like `reminders__set_reminder`, `flows__list_flows`, `flows__recap` and `palui__search_tools` (they were Indonesian, like `ingatkan` and `daftar_flow`). Palui still answers in Indonesian. A flow you wrote by hand with an old built-in tool name fails its check until you update the step.

### Fixed

- Sending a saved file to an MCP tool is safer and clearer. After the agent reads something untrusted (a web page, an external server), a call that carries a saved file always waits for your yes, even with "Allow every tool without asking". The approval message names the file and its size instead of an id. Flows never send a file that outside data picked. A server that repeats the file back no longer fills the agent's context, and one call carries at most 15 MB of files.
- The agent is told right in the attachment results how to hand a file to another app (upload it there with its `fileRef`, then use that app's id), so it stops passing Palui's own file id and getting "File not found".
- A photo or document saved in chat can now go to another app's MCP tool, like uploading a receipt to a finance app and attaching it to a transaction. Before, the agent passed Palui's own file id, the app answered "File not found", and the receipt stayed in Palui only. Files only go to MCP servers marked as your own, never to external ones.
- Clicking Connect on a connector that's already running no longer leaves it stuck on Connecting. It goes back to On (or its error) right away. On a connector waiting to retry after an error, Connect or a saved fix like a new token now retries at once instead of up to 10 minutes later.
- Adding a connector from an agent's Tools tab now has a back link to that agent, not to the Connectors page.
- WhatsApp and Telegram show their own logos in the dashboard and docs, not a speech bubble and a paper plane.
- A flow run with a chain of check-in reminders no longer shows as missed when you answered a later reminder. `flow_history` and recaps read the check-in that decided the run, and a late answer corrects that same one.

## 0.7.0 (2026-11-12)

### Breaking

- Routines are gone; flows do everything they did. The routine engine, the routine tools (`buat_rutinitas` and the rest), the Routines page, the `palui flows status` and `palui flows mode` commands and the old routine answer buttons are removed, and the app deletes the Routines connector on start. Routines that weren't handed over to flows stop firing, so if `palui flows status` on 0.6.0 still shows routines, run `palui flows mode flows` there and wait a minute before you upgrade. The routine tables stay for one more release, so rolling back to 0.6.0 still works.

### Added

- Agents can message other people for you. Say "chat Budi sekarang, bilang gue otw", "malam ini jam 8 chat Budi, ingetin dia gue otw" or "tiap Jumat jam 11 kabarin Siti", and the new builtin Messages to contacts connector sends it now, at that time or on a repeat. It only sends to saved contacts, and each agent has its own list. A new number is saved when you approve the first message to it. Every message shows you the recipient, the time and the exact text first, unless you set that contact to Always allow on the new Outbound page, and even then only when you named the contact yourself in a turn no web page, tool result or webhook touched. Messages sent now wait 15 seconds with a Batalin button (or reply "batal"). A flow's message step can send to a contact with `contact`, approved once per flow version. The Outbound page has a kill switch, daily limits (5 per contact, 20 in total by default), an optional signature, scheduled messages and a log of every send. WhatsApp messages go out from the number Palui is linked to. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- A flow check-in's deadline can now be computed. `{kind:"at", at:"{{steps.nextp.data.next.timestamp}}", plusMin:-10}` stops it 10 minutes before a time a tool returned, `{kind:"next", plusMin:-10}` stops it 10 minutes before the schedule's next occurrence, and `after` takes a template like `"{{vars.left}}"`. A deadline that has already passed skips the ask and takes `onMissed`, so a reminder chain like "last reminder 10 minutes before the next prayer" works whatever the gap between prayers is.
- Flow expressions get `choose(cond, a, b)`, which returns `a` when `cond` is true and `b` otherwise. "Remind at +70 minutes unless that's within 10 minutes of the last reminder" is now `choose(trigger.at + 70 * 60000 <= vars.last - 10 * 60000, trigger.at + 70 * 60000, vars.last)`.

### Changed

- The default turn time limit is now 5 minutes instead of 2. A slow model (Opus on high effort) spent 70 to 80 seconds on each step that wrote a flow draft, so a 2 minute turn fit one such step and then had to stop and say it ran out of time. An install that saved its budgets keeps its own value; change "Turn time limit" in Settings or ask Palui to.
- A flow run can send 10 messages instead of 5. A prayer check-in chain (the ask, reminders at +10, +30, +70 and +150 minutes, and a last one before the next prayer) is six asks, and the Zuhur and Isya runs failed with "More than 5 messages in one run". Re-asks and missed notes still don't count.
- The newest call of each tool keeps its arguments in the history up to 32,000 characters, so the next turn sees the flow draft it wrote last time instead of "arguments left out of the history" and fixes it rather than rebuilding it. Older large calls are still left out.
- A flow id or set value name that breaks the naming rule now gets a problem that quotes the name (`"Init": Ids use lowercase letters...`, `Key "L": Variable names use...`) instead of "Invalid key in record", and buat_flow spells the rule out.
- A flow's page now draws its steps as a graph: triggers on top, each step as a card, branches as labelled arrows, and an "ends" mark wherever a run can finish. Click a step to read it in full under the graph.

### Fixed

- A turn that runs out of time no longer ends in silence. When the next step probably won't fit in the time left, or it's the last allowed step, the model is told to answer now with no tools. If a turn still times out, the chat gets a short note saying what ran, whether anything changed, and to say "lanjut" to continue, and the next turn sees that note too.
- On the Flows page, clicking anywhere on a flow's row now opens it. Before, only the flow's name was a link, so most of the row did nothing.

## 0.6.0 (2026-11-12)

### Added

- Palui can read its own setup and change its settings from chat. Ask "timezone kamu apa?" or "ganti model fast ke claude-haiku-4-5" and the new builtin Settings connector looks up or changes the timezone, language, model roles, budgets and fallback channel. Every change asks you first, only Palui (not other agents) can make one, and secrets are never shown.
- `/report` in any chat replies with a debug snapshot of that chat: chat and session ids, recent runs with every tool call they made and the approvals behind them, the last 10 messages, unsent outbox rows, recent warnings and state changes (flows, routines, approvals, reminders), what the chat has scheduled right now, where the database lives and a dashboard link. It stays within one WhatsApp or Telegram message and says what it left out. Add a note after it (`/report it answered twice`) and paste the reply into a coding agent; sent without a note, the reply asks for one next time. Each report gets an id (`rpt_...`) and is saved in the database, so the id alone is enough later. In a group the report goes to your own chat and the group only sees the id. A flow can no longer use `/report` as its chat trigger. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Eight new chat commands. `/help` lists the commands, including the ones your flows answer to. `/usage` shows today's tokens and runs by model and agent. `/models` lists what each model connector offers, and `/model <name>` puts a model first for a role (the same setting as the dashboard's Settings page). `/tools` shows the tools a turn in this chat would get. `/btw <question>` answers a side question without adding it to the session. `/compact` folds the older messages into the session summary now. `/id` shows the chat, session and message ids, and the ids of a message you quote.
- Ask Palui to turn a routine into a flow and it keeps the routine's schedule, pause state, open check-ins and whole log (the new `jadikan_flow` routine tool). Before, replacing a routine meant deleting it, and its history and shadow flow went with it. Deleting a routine now says plainly that its log goes too.

### Changed

- `/help`, `/models`, `/model`, `/usage`, `/btw`, `/compact`, `/tools` and `/id` are now built-in commands, so a flow can't use them as its chat command. A flow that already does stops answering to it: give it another command.

### Fixed

- On WhatsApp, "typing…" no longer flashes for a split second and disappears before the ⏳ reaction. The reaction now goes first and typing starts about 1.5 seconds later, and a reply that comes faster than that skips typing altogether.
- After you approve a tool, Palui no longer trusts lists it read in the same step before your answer. It used to say a delete hadn't worked because a list taken a second earlier still showed the item.
- A routine's shadow flow no longer blocks a flow you create with the same name. Shadow flows are now hidden from every flow tool, not only the list, and the shadow one moves aside to `<name> (rutinitas)`.
- Checking a draft flow now finds the recap tool (`flows__ringkasan`) for a recap step, and a re-ask that uses the routine-style `{{n}}` points to `{{run.followUps}}`.

## 0.5.0 (2026-11-12)

### Added

- A Routines page in the dashboard lists every routine across your chats with its schedule, next time, action, recap and anything that needs a look: a failing source, a source connector that's missing or off, or a check-in waiting for an answer. Open one to see it drawn as the steps it runs (when, ask or send, what happens with no answer, recap), its next times, done per item, and its log with counts per status, filtered by date. You can pause, pause until a time, resume or delete it there; creating and editing stays in chat.
- Each agent now has its own page (`/app/agents/<slug>`), opened from its row on the Agents page. It holds the profile, the shared-chat rules, the daily cap with today's usage, the recall container, its standing instructions (add, edit, switch off and delete them right there) and the chats it answers in, each with its Answer here switch. New agent asks only for a name, slug and persona, then opens that page.
- Flows: automations Palui builds from chat out of triggers and steps. A flow starts on a schedule, a webhook, a chat command or phrase, a value that changes, another flow's check-in or run, or by hand, and its steps call tools, branch on conditions, set variables, send messages, ask check-ins, wait, run a prompt, or repeat for each item in a list. Nothing calls the model unless a prompt step asks, and every run is logged step by step, skips included. Ask in chat; Palui checks and dry-runs a flow before saving it, and `kenapa_flow` explains why one didn't run. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- Write tools in a flow are approved once per flow version. A run still asks when an argument comes from outside data, when a tool's class changed, or when the tool is set to ask every run (the new "In flows, ask" setting on an MCP server's tool list). Destructive tools never run in a flow.
- A read-only Flows page in the dashboard lists every flow with its next time and last run. A flow's page shows its steps and branches, versions and recent runs, and a flow run opens its step log on the run page.
- Webhooks get a third mode, `flow`: the body starts the flows listening to that hook, deduped by the `x-palui-delivery` or `X-GitHub-Delivery` header. Saving a flow with a webhook trigger switches its hook to this mode.
- `palui__cari_tool` results now say each tool's class and whether its output is untrusted.

### Changed

- Routines are moving to flows. After this upgrade each routine also gets a flow that runs in shadow: it computes the same times but sends nothing, and differences are logged (the Flows page and `palui flows status` show the count). The routine engine keeps sending until you run `palui flows mode flows`, which hands over with open check-ins and old buttons intact; `palui flows mode legacy` goes back. After the handover the routine tools edit flows, and the Routines page links each routine to its flow and pauses or deletes the flow along with it.
- Prompt caching now works between turns, not only inside one. The clock, recall and check-ins moved out of the system prompt to the end of your newest message, so the model can reuse the tools, the system prompt and the earlier conversation it already read. Against CLIProxyAPI, a follow-up turn read 98% of its input from the cache where it read none before.
- Tokens read from the prompt cache now count at 10% against the global, agent, job and flow daily caps, about what they cost next to fresh input. Fresh input, cache writes and output still count in full, and `/status` shows the weighted number. On 2026-11-11 the old count paused turns at 2.03M tokens when about 0.8M was real cost.
- A run's page (Activity) shows input read from the cache and input written to it separately, plus what the run counted toward the caps. Adds a migration; rolling back past this release needs the pre-deploy snapshot.
- The global daily token cap (Settings, Limits) can now be set to 0 to turn it off, the same as an agent's or a job's cap, so turns never pause on token use. `/status` shows `tanpa batas` when it's off.

### Fixed

- Raising the daily token cap or runs per hour (or setting the token cap to 0) now lifts a budget pause on the next message instead of at midnight, and `/status` shows the cap that applies now. Before, a pause stayed until midnight even after you raised the cap, and turns could fail once that pause ran out.

- Every capability is a connector of kind `channel`, `model`, `memory`, `tools` or `skill`.
- Pause, resume and remove from the dashboard, from chat or from the CLI, with no restart.

- CLIProxyAPI and ai-gateway as model providers, with per-role failover.

- A persona in Settings that shapes how Palui talks.

- Reminders in natural language, with RRULE recurrence, IANA zones, Done and Snooze, and delivery that survives restarts.

- Every page holds up on a phone and with very long names, big numbers and empty lists.

- Docker Compose with two services from one image and one SQLite volume.
