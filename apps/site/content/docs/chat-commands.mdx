title: Chat commands
description: Reference for every chat command, from /help and /status to /model, /btw, /id and /report, plus the approval and reminder replies Palui understands on every channel.
---

Commands start with a slash. The router handles them before anything else, so they never start a turn, and all but `/btw` and `/compact` work even when every model connector is paused. Only the owner can use them. From anyone else they're plain text: in a chat with an agent they go to the agent as a normal message, and anywhere else they're dropped.

## Commands

| Command | What it does |
|---|---|
| `/help` | Lists the commands, including the ones your flows in this chat answer to. |
| `/connectors` | Lists every connector with its state. On Telegram each one has an inline button to flip it. |
| `/connectors on <id>` | Turns a connector on (resumes it). |
| `/connectors off <id>` | Pauses a connector. Credentials are kept. |
| `/new` | Starts a new session in this chat. recall auto-save runs for the one you just closed. |
| `/stop` | Aborts the turn that's running in this chat. |
| `/compact` | Folds the older messages of this session into its summary now. The last 6 stay as they are. |
| `/btw <question>` | Asks a side question. The session is the context, but the question and the answer stay out of it. |
| `/status` | Shows the model in use, tokens used today and connector states. |
| `/usage` | Shows today's tokens and runs, by model and by agent, for this chat, and the last 7 days. |
| `/model` | Shows the model chain of each role (`default`, `fast`, `vision`). |
| `/model <name>` | Puts that model first for `default`. `/model fast <name>` and `/model vision <name>` set the other roles. |
| `/models` | Lists the models each model connector offers. `/models <word>` filters, `/models <id>` shows one connector. |
| `/tools` | Counts the tools a turn in this chat would get, per connector and class. `/tools <id>` lists one connector's tools. |
| `/id` | Shows the chat, session and message ids. Quote a message to get its ids. |
| `/report` | Replies with a debug snapshot of this chat to paste into a coding agent. |
| `/report <note>` | Same, with your note on what went wrong at the top. |
| `/agent` | Shows which agent answers in this chat and lists the agents. |
| `/agent <slug>` | Gives this chat that agent, turns it on and starts a new session. Works in a group Palui isn't answering yet. See [Agents](/docs/concepts/agents). |
| `/agent off` | Goes back to Palui. Other people in this chat stop getting answers. |
| `/reply all` | In a group, answers every message instead of only mentions and replies. |
| `/reply mention` | In a group, answers only @mentions and replies to the agent again. This is the default. |

`<id>` is the connector id shown by `/connectors`, for example `telegram`, `cliproxy` or `recall`.

### /connectors

```text
/connectors off recall
/connectors on recall
```

Connecting a new connector and removing one stay in the dashboard. Chat only pauses and resumes. Pausing applies from the next turn. See [Connectors](/docs/concepts/connectors).

### /model and /models

```text
/models claude
/model opus
/model fast cliproxy/claude-haiku-4-5-20251001
```

`/model <name>` takes a full model id or a part of one. If the part matches several models, the reply lists them and nothing changes. The model goes first in the role's chain on every running connector that offers it, and the old chain stays behind it as the fallback. Write `<connector>/<model>` to pick one connector.

This is the same setting as Models on the dashboard's Settings page, so it holds for every chat and agent, from the next message on. Messages with images use the `vision` role, which `/model <name>` doesn't touch.

### /btw

```text
/btw itu tadi hotel yang mana?
```

A side question gets one answer from the `default` model with no tools. It sees the session's summary and latest messages, but nothing is added to the session, so the next turn reads the same history as before. Its tokens count toward the daily cap. It answers while a turn is running too.

### /compact

Palui compacts a session on its own past about 40 messages. `/compact` does it now, whatever the length, and waits for a running turn to finish first. Unlike `/new`, the session goes on: the `fast` model writes the summary and the last 6 messages stay as they are.

### /id

```text
/id
```

Without a quote it shows the chat id, the session id, the agent and the id of the `/id` message itself. Quote any message and send `/id` to see that message's id, its run and its session. For something Palui sent without a turn (a command reply, a reminder, an approval prompt) it shows the outbox id and what sent it.

### /report

```text
/report it answered the same message twice
```

The reply is plain text written for a coding agent, not for you. It holds:

- the chat, session and agent ids, the Palui version and a link to the chat in the dashboard
- the last five runs plus the runs behind the messages shown, each with its status, model, tokens and error, and any tool call that didn't finish ok
- the last ten messages, with the reason when one was stored but ignored
- outbox rows still waiting, and ones that failed in the last 24 hours
- warnings from the last 24 hours that name one of those runs, messages or outbox rows

Paste it into the agent working on your Palui checkout and it knows which rows to look at in `palui.db`. A long report can arrive as two messages; copy both, or use the id.

Every report has an id on its first line, like `rpt_...`, and the same text is saved in the `reports` table. If you only kept the id, that's enough: the agent can read the report back from the database.

In a group, or any chat other people are in, the report goes to your own chat with Palui and the group only sees the id.

The report quotes messages from the chat, other people's included, and the chat's address on the channel (on WhatsApp that's a phone number). Known token formats are masked, but read it before you paste it into a service you don't run.

### Your own commands

On the dashboard's Commands page you can save a prompt under a name of your own, like `/report-fix`, for every agent or for one agent. Typing it runs a normal turn with that prompt, so the agent can use its tools. `{{args}}` in the prompt becomes whatever you type after the command.

Turn on "Attach a debug report" and the agent also gets the same snapshot `/report` makes. With a prompt like this one, `/report-fix it answered twice` hands the problem straight to a coding agent:

```text
Start a T3 Code thread in the palui project to find and fix the problem in the debug report below. Owner's note: {{args}}

Put the whole report in the task. Reply with the thread link only.
```

Commands with a report only run in your own chat with Palui, since the report holds your details. Built-in commands and flow commands win when a name is taken twice, and an agent's own command wins over one for every agent. `/help` lists yours at the end.

### Switching off the channel you're on

`/connectors off telegram` sent from Telegram is allowed only when another channel or the dashboard is reachable. The reply tells you how to turn it back on. If nothing else is reachable, the command is refused, so you can't lock yourself out. The same rule applies to WhatsApp.

### When the model is off

If the only model connector is paused, any normal message gets this fixed reply:

```text
Model lagi off. Nyalakan: /connectors on cliproxy
```

(The model is off. Turn it on with this command.) `/btw` gets the same reply. The other commands and plain reminders keep working.

## Approval answers

When a tool needs your approval, Palui sends a prompt. Answer it with:

| Channel | Approve | Deny |
|---|---|---|
| Telegram | The approve button | The deny button |
| WhatsApp | `ya` (yes) | `batal` (cancel) |
| Dashboard | Approve on the Chats page | Deny on the Chats page |

The router matches the answer to the pending approval, so it isn't sent to the model as a message. No answer within 10 minutes counts as a denial. See [Approvals](/docs/concepts/approvals).

## Reminder replies

A fired reminder offers Done and Snooze for 10m, 1h or tomorrow 09.00.

- Telegram: tap the inline buttons.
- WhatsApp: quote the reminder and reply.

```text
done
tunda 1j
```

(`tunda 1j` means "snooze 1 hour".) See [Reminders](/docs/concepts/reminders).
