title: Self-hosting
description: Run Palui with Docker Compose as one service and one SQLite volume, configured by two keys in .env.

Palui runs as one Compose service with a single data volume.

<ArchitectureDiagram>
  Messages arrive from three channels: WhatsApp, Telegram and the dashboard web chat. They flow into the one Palui container, which holds the router, agent turns, the scheduler, the outbox and the connector supervisor, and also serves the dashboard, the API, authentication, the /health endpoint and database migrations. It keeps one SQLite database and the WhatsApp session on a single volume. Model providers, the recall memory service and MCP servers sit outside the container and are reached over the network.
</ArchitectureDiagram>

`palui serve` is one Go process. It runs the channel sockets, agent turns, the scheduler, the outbox and the connector supervisor, and it serves the dashboard, the API, auth and `/health`. It also runs the database migrations on start. A deploy restarts it, and the durable inbox and outbox are what keep messages safe through that, see [Upgrades](/docs/self-hosting/upgrades).

## compose.yaml

A trimmed example. The repository's `compose.yaml` is the real one.

```yaml
services:
  app:
    build: .
    image: palui:latest
    restart: unless-stopped
    env_file: .env
    environment:
      DATA_DIR: /data
    ports:
      - "127.0.0.1:4802:3000" # loopback only, your tunnel connects here
    volumes:
      - palui-data:/data
    healthcheck:
      test: ["CMD", "palui", "healthcheck"]
      interval: 30s
      start_period: 30s
      start_interval: 2s
    stop_grace_period: 60s

volumes:
  palui-data:
```

The rules behind it:

- One service. The image is about 37 MB: a distroless base (CA certificates, no shell or package manager) and the `palui` binary with the dashboard built in.
- The healthcheck is liveness only: `/health` answers 200 unless the database schema is newer than the code. Connector state goes in the `/health` body, never in the exit code, so a WhatsApp outage can't fail a deploy.
- `stop_grace_period: 60s`. On SIGTERM the server drains: it stops taking new turns, finishes the current step and releases its outbox claims.
- `app` is bound to `127.0.0.1`. Your tunnel is the only way in.

The same binary is the admin CLI. Run any command with `docker compose exec app palui <command>`: `owner invite`, `connectors list`, `backup`, `secrets-check`, `version`.

There's no shell in the container, so `docker compose exec app sh` doesn't work. To read `/health` from inside, run `docker compose exec app palui healthcheck --print`. For file work on the volume, start a throwaway container that borrows it:

```bash
docker run --rm -it --network none --user 1000:1000 --volumes-from palui-app-1 alpine:3.24.4 sh
```

## Volume

One volume, mounted at `/data`:

| Path | What it holds |
|---|---|
| `/data/palui.db` | The SQLite database (WAL mode): connectors, encrypted secrets, chats, reminders, jobs, everything |
| `/data/wa/` | The WhatsApp linked-device sessions, one SQLite file per WhatsApp connector |
| `/data/backups/` | Pre-deploy snapshots |

There are no JSON state files. Every write goes through a database transaction. Retention: tool call arguments and results are kept 30 days, media 14 days, events 90 days.

## The two keys

`.env` holds two keys. Every other credential is entered in the dashboard and stored encrypted in the database.

| Key | What it is |
|---|---|
| `MASTER_KEY` | Encrypts every connector secret (AES-256-GCM). Generate with `openssl rand -base64 32`. |
| `APP_URL` | The public origin of the dashboard, like `https://palui.example.com`. Used for cookies, the passkey domain and invite links. Use a host name: passkeys don't work on an IP address, so with `http://192.168.1.20:4802` the server starts but passkey sign-in is off (an owner invite still signs you in). |

<Callout type="warn" title="Keep a copy of MASTER_KEY">
  Store `MASTER_KEY` in your password manager. Every connector secret is encrypted with it. If you lose it, a restored backup can't decrypt any API key or bot token, and you'll have to enter them all again.
</Callout>

## Logs

```bash
docker compose logs app
```

Channel, turn, scheduler and dashboard problems all show up there. Logs are JSON lines tagged with run, chat and connector ids, with secrets redacted.
