---
title: Security model
description: "How Palui keeps one owner in control: passkeys, owner claims, approvals, the taint rule, encrypted secrets and a closed network."
---

Palui has one owner and assumes everything else is untrusted: other people messaging the bot, web pages, webhook payloads and tool results from servers you don't run.

## Dashboard access

- Passkeys only. Sessions live in the database and last 30 days.
- There's no way to create an account over HTTP, from the first boot on.
- The owner account comes from `docker compose exec app palui owner invite`, a single-use link valid for 15 minutes. You need shell access to the Docker host to run it.
- The same command is the recovery path for a lost passkey.
- App routes are `noindex`.
- AI agents reach the MCP server at `/mcp` only with a bearer token: a personal token, or an OAuth connection you allowed while signed in. Both are listed and revocable in Settings, and stored as hashes. See [MCP access](/docs/mcp-access).

## Channel owner

- Telegram: claimed with a one-time `t.me` link carrying a nonce. The nonce is single use and expires after 10 minutes.
- WhatsApp: your phone number, entered in the wizard, plus the LID Palui learns from your first DM.
- Members are never the owner. Commands, approvals and buttons stay yours.
- Everyone else is dropped silently. Palui doesn't reply, and the drop is logged with the reason.

## What the agent may do

- Tool classes fail closed. Every tool is `read`, `write` or `destructive`, and an unclassified tool is `destructive`. See [Tool classes](/docs/concepts/tool-classes).
- Approvals. In your own chats, `destructive` tools always ask you first. The runtime enforces it, not the prompt. See [Approvals](/docs/concepts/approvals).
- The taint rule. In your own chats, once a turn reads untrusted content (web fetch, a webhook payload, an `external` MCP server), every `write` tool needs approval for the rest of that turn. See [The taint rule](/docs/concepts/taint-rule).
- Shared chats. A group or someone else's DM only gets tools whose data stays in that chat or that keep nothing (reminders, saved files, web search, web fetch). Nothing there asks for approval and destructive tools are never offered. Accepted risk: anyone in the chat can make the agent change that chat's reminders and saved files, and nothing past it. See [Agents](/docs/concepts/agents).
- Members. A member's DM, or a WhatsApp group where everyone is you or a member of that agent, also gets the agent's own data: its MCP servers, notes, contacts and memory. Still no approvals and nothing destructive. Every doubt (an unreadable group list, a Telegram group, an agent with no members) falls back to the shared chat rules above.
- Jobs and hooks. Scheduled jobs never get `destructive` tools, and every `write` needs approval. Webhook summaries run with zero tools.
- Budgets. Each turn is capped at 12 steps, 120 s and about 64 tools loaded up front (more load on demand through tool search). Daily token caps and a limit of 60 runs per hour stop runaway loops.

## Memory

recall auto-save stores only your messages and the final replies. It never stores tool output and skips tainted turns, so an injected tool result can't become a permanent memory that auto-recall feeds into every later turn.

## Secrets

- Connector secrets are encrypted at rest with AES-256-GCM, keyed by `MASTER_KEY` from `.env`.
- They're write-only. You can replace one, never read it back. The UI shows them masked, like `rcl_••••a91f`.
- Logs redact API key patterns (such as `rcl_`, `zkg_` and `sk-` keys) and bot tokens.
- `.env` holds only two keys: `MASTER_KEY` and `APP_URL`. Keep a copy of `MASTER_KEY` in your password manager.
- Backups are encrypted with age before they leave the machine. See [Backups](/docs/self-hosting/backups).

## Network

- The app is bound to `127.0.0.1` on the Docker host and reached through your tunnel.
- Palui is one process, so there's no internal API between services to protect.
- An SSRF guard sits in front of every fetch the agent can steer, so a page or a prompt can't make Palui read internal addresses.

## Retention

| Data | Kept for |
|---|---|
| Tool call arguments and results | 30 days |
| Media | 14 days |
| Events | 90 days |

Messages stay in the database. Compaction only removes old messages from the model's context.

## Model provider logs

Palui sends prompts to your model provider. If that provider logs requests to disk (CLIProxyAPI can), your prompts and any recall memories in them end up there. Cap or disable those logs.
