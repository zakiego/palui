# Palui dashboard: design

The contract is `docs/PLAN.md` section 11. This file records how the build meets it and the calls made along the way.

## Contract (from PLAN 11.1)

- Audience: one technical owner, often on a phone between other things.
- Primary task: see that Palui is alive, and flip a connector in seconds.
- Category default: a chatbot SaaS dashboard. Predictable opposite: a raw settings list.
- What's specific: health and control are the same element. Every connector shows on, paused or broken, and it's one tap from off.
- Required states per page: loading (Skeleton in the final layout), empty (Empty with the one next step), error (Alert with cause and fix), long content, 390 px.
- Finish counts: 1 accent hue, radius only from `--radius` steps, 0 emoji in chrome, 0 gradients, 0 inert controls.

## Foundations

- Linear's look (TASTE.md "Reference look: Linear"): ui-sdk components (`src/components/ui`) on the token file `src/styles/app.css`. Linear's neutrals (`#08090a` chrome and `#0f1011` panels at night, near white by day), Inter at weights 510 and 590 with `cv01` and `ss03`, Geist Mono for machine values, `--radius: 0.5rem` (4, 6, 8, 12 px steps), the `emphasized` and `drawer` easings.
- One indigo, `--brand` (`#5e6ad2`): the focus ring, an "on" Switch, text selection at night and the caret. Never a button fill, gradient or tinted surface. Primary buttons are ink by day and an inverted light pill at night.
- Buttons are 32px pills with 13px labels at 510 on every pointer (TASTE.md). Cards are a 1px hairline ring with no soft shadow and 24px padding from `sm` up.
- Shell: the `sidebar-07` layout (collapses to icons, a Sheet on a phone), a 48px sticky header with the page title, the global status and a "Search ⌘K" pill. The sidebar shows the mark and name only; rows are 32px, 13px at 510, the active one a raised hairline plate.
- Machine-written values (ids, model names, token counts, RRULEs, times) are Geist Mono with tabular numbers.
- Status is always a word plus an icon: on = green + check, paused = zinc + pause, error = red + alert, connecting = Spinner, not set up = dashed circle. See `src/components/connector-status.tsx`.
- Copy: English UI strings through `src/lib/i18n` (`en`, `id`). No em dashes anywhere.

## Motion (PLAN 11.6)

| Element | Decision |
|---|---|
| Connector Switch | track color 150 ms; the white thumb slides in 200 ms on `cubic-bezier(0.16, 1, 0.3, 1)`, a transition so it retargets |
| Sidebar and table rows | hover shows at once and fades out over 150 ms |
| Status change | `.status-tone`: 150 ms color crossfade, no movement |
| Sheet / Drawer | Sheet slides 2.5rem and fades; Drawer is ui-sdk's, drags to dismiss and moves itself. `ResponsiveSheet` opens one commit after mount so a sheet that mounts open still slides in, and pages keep the last content while it closes so the exit plays |
| Home connector map | `.map-trunk` / `.map-branch`: the wires draw once ever behind a localStorage flag (40 ms linear trunk per row, chained, then a 120 ms branch), then static. Busy means a Spinner badge, no pulses |
| Rows chevron | 150 ms rotate on the emphasized curve, a CSS transition so it retargets |
| Accordion panel | height 200 ms open, 150 ms close, emphasized curve, a CSS transition so a quick second tap turns it around; chevron as Rows. Used by the agent Tools tab |
| Login and invite | `.stagger-in`: 300 ms rise of 8 px, 60 ms apart, mount only (rare screens) |
| Agent reply | `.agent-in`: 150 ms opacity once when its text starts streaming. The owner's own messages never animate |
| Command menu (⌘K) | none: opened from the keyboard many times a day, so it appears at once, 13vh from the top |
| Tables, lists | none |
| Skeletons | `.skeleton-shimmer`: one band of `--skeleton-highlight` crosses the viewport (gradient fixed to the viewport, `background-position` -100vw to 100vw in the first half of 1800 ms, linear, then rests), so every block lights up as one sweep. Static under reduced motion. Each page's skeleton is built from its real Card, Table, Item and Field pieces (`src/components/page-pending.tsx`) |
| Slow page load | `PagePending` (every route's pendingComponent, shown after 300 ms): the skeleton fades in over 200 ms, and when it leaves `#main-content` fades from 0.4 to 1 in 200 ms (WAAPI), both on the emphasized curve. A fast switch never shows a skeleton, so it never fades: there's still no route entrance. "Loading <page>…" goes to the shell's `#page-status` live region |
| Navigation wait | `RouteProgress`: a 2 px `--foreground` bar on the header's bottom edge, only after 150 ms and only when the URL changed (not `router.invalidate()` refreshes). Runs to 85% over 4 s on the emphasized curve, fills in 200 ms, fades 150 ms later |
| Toasts | Sonner default |
| Reduced motion | everything instant (the global rule in `app.css`); spinners keep turning; skeletons stay still and the page doesn't fade |

## Interaction (PLAN 11.5)

- Pause never asks: the Switch moves at once and a Sonner toast offers Undo. Remove always asks, in an AlertDialog that names the consequence (`manifest.removeWarning`).
- Test, Connect and Run now use `toast.promise`.
- Sheets become Drawers under 768 px (`src/components/responsive-sheet.tsx`).
- The connect wizard keeps progress as a `not_set_up` draft when the sheet closes.
- The header status is live over SSE and announced through `aria-live="polite"` once per change, never on load.

## Decisions

- 2026-11-10, accent (provisional): Banjar sasirangan indigo is the one accent hue, `oklch(0.45 0.15 270)` in light and `oklch(0.7 0.13 270)` in dark (label flips to ink at night). It drives `--primary` (buttons, the active Switch, my chat bubbles, the mark) and `--chart-1`. Chosen from PLAN 11.2's candidates because it can't be read as a status: green is on, zinc is paused, red is broken, and amber was already out. Provisional until the M3.5 Explore. The Explore (below) kept it: the Board variant's plugged cables use it too, and nothing in the three variants needed a second hue. Superseded on 2026-11-13 by the Linear redesign below: indigo stays the one accent but no longer fills `--primary`, buttons or chat bubbles.
- 2026-11-10, Connectors page layout (Claude's pick, Zaki to confirm): the PLAN 11.7 Explore ran on real data with three variants. 1 Cards, a card grid grouped by kind with a Switch per card (axis: closest to TASTE.md and shadcn). 2 Rows, dense Raycast or macOS settings rows with inline status and a chevron that opens the details in place (axis: density). 3 Board, a wiring board with Palui in the middle, channels plugged in on the left and everything Palui uses on the right, a solid cable when running and a dashed one when unplugged (axis: spatial). Kept: Cards. Why: it follows TASTE.md most closely (an icon on every node, big labelled cards instead of small controls) and is the layout PLAN 11.4 describes, the card shows the one-line summary, status, Switch and Open without an extra tap (Rows hides the details behind the chevron), and it holds up at 390 px with long MCP names, where Board doubles the page length and its left column floats beside a tall right one on desktop. Board is the most specific to the product and the best runner-up if the Home map ever needs to carry more. To compare: open `/app/connectors?v=1` (Cards), `?v=2` (Rows) or `?v=3` (Board); the picker sits at the bottom, and 1, 2, 3 or the arrow keys switch. Without `?v` the page shows the pick (`DEFAULT_CONNECTOR_LAYOUT` in `src/components/connectors/layouts.ts`). On confirm, delete the other two variants, the picker and the `v` search param.
- 2026-11-10, Home connector summary: a connector map that follows the Cards pick. Palui sits at the root and every connector hangs off one wire, grouped by kind, each with an icon tile, its status word and icon, and its Switch. The wires draw once ever (the `palui.homeMap.drawn` localStorage flag): each row's trunk segment takes 40 ms, linear, chained so the wire reads as one line, then each branch reaches out in 120 ms on the emphasized curve. Then it's static. A connecting connector shows the Spinner badge, never a pulse. Reduced motion: no draw. Known limit: on a first ever visit that's a full page load (not a client navigation), the static wires paint before hydration and then draw once; the usual first visit comes from the invite flow, which is a client navigation.
- 2026-11-10, chat Markdown: agent replies render a small safe subset (bold, italic, inline code, fenced code, bullet and numbered lists, links and bare URLs) through a hand-written parser in `src/lib/markdown.ts` that returns a tree, rendered as React elements in `src/components/markdown.tsx`. No raw HTML, no `dangerouslySetInnerHTML`, links only for http, https and mailto with `rel="noopener noreferrer"`. Chosen over react-markdown because the subset is small, needs no plugin chain, and the parser is unit-tested in `markdown.test.ts`. The owner's own messages stay plain text.
- 2026-11-10, Drawer: shadcn's base-nova `drawer` (Base UI's Drawer) instead of a hand-wired vaul, because the shadcn component is the house rule. It has the same drag-to-dismiss behavior.
- 2026-11-10, toasts: Sonner (`components/ui/sonner.tsx`, reading this app's theme provider) instead of base-nova's Base UI toast, because PLAN 3.2 names Sonner.
- 2026-11-10, chat: shadcn's chat primitives (`message-scroller`, `message`, `bubble`, `trace`) for the transcript and inline tool calls, instead of AI Elements.
- 2026-11-11, model chain row: each step's Move up, Move down and Remove now live in one per-step actions menu (shadcn `dropdown-menu`, a 40 px ghost trigger on touch) instead of three inline icon buttons. The three 36 px buttons, 4 px apart with Remove next to Move down, forced a ragged wrap at 390 px, so the model input started at the card edge instead of under the select. With one trigger the row fits a phone in two aligned lines (index and connector, then model id and menu) and stays one line from `@2xl/main` up. Rows key on a client-only id, so focus follows a moved step. Screenshots: `docs/screenshots/ui-fixes-*.png`.
- 2026-11-11, routine detail page: an Explore after two polish passes the owner rejected ("current is bad", "still bad"). Three variants on real data behind the prototype picker. 1 Timeline, today on a time axis with a now line plus an item-by-day grid for the last 7 days, config as four sentences (axis: time first). 2 Flow, the routine drawn as its steps on a wire (When, Ask or Send, No answer yet, Missed, Recap), with Up next and per-item done bars beside it (axis: structure). 3 Inspector, the log as the page with one-tap status filters and every setting in a properties sidebar like an issue tracker (axis: density, two panes). Kept: Flow. Why: "I love flow". It is also the shape the planned Flows feature (multi-step automations) will have, so the page grows by adding steps instead of being redesigned.
- 2026-11-12, agent page sections: the five sections (Settings, Chats, Instructions, Memory, Tools) are Geist-style line tabs (`TabsList variant="line"` in `components/ui/tabs.tsx`): icon, name and count on a full-width hairline, a 2px foreground bar under the active one, color only on hover, nothing slides. The owner asked for https://vercel.com/geist/tabs, replacing the big radio choice cards built earlier that day. The section stays in `?tab=`. Settings and Memory panels use `keepMounted` so unsaved edits survive a switch. The header, tabs, every panel and the save bar share one `max-w-3xl` (before: header uncapped, cards 5xl, panels 2xl, Tools 3xl), because the owner asked for a consistent width.
- 2026-11-12, flow page: the same line tabs, in `?tab=`: Steps (triggers, the graph, the changes it may make), Runs (then the saved state) and Versions, under the header and the last-error alert, all at `max-w-3xl`. Runs shows no count because the list is capped at 30. Card titles that repeated the tab name are gone.
- 2026-11-12, agent Tools tab: the flat list of every tool (about 4,500 px on the worst fixture) is now two parts, "Only this agent" and "Global", because the owner asked to split the tools by who can use them. The owner then asked for them left and right behind a click, so the two parts are big choice cards side by side (icon, title, count, a radio; same style as the section cards above), with Add MCP at the end of that row. Each server is one closed accordion row (icon tile, name, tool count, destructive count) that opens in place to its scope select, an Open link and the tool rows. Changing the select moves the server to the other part, switches the cards to it, keeps it open and puts focus back on the select. A search opens every group with a hit, and shows the other part when the picked one has none and clearing it restores what was open. An Explore with three variants (Rows, Split as list plus detail pane, Risk grouped by destructive, write, read) ran first; the owner answered with this split instead of picking one.
- 2026-11-12, Home layout: problems first. A "Needs attention" card (only when something is in error, or switched on but paused) shows up to three of them with their reason, each linking to its connector page. Under it, the left column has Tokens today (the number, in/out/runs, and a bar per day for the last 7 days, today in ink), Next reminders as an agenda (time and date on the left) and Last runs. The connector map is the right column, and it comes last on a phone, where it used to take the first screen. The owner asked for a better, more beautiful Home and approved this plan in chat, so no Explore ran. The chart doesn't animate on mount and isn't a Tab stop, since Home is opened many times a day and refreshes live.
- 2026-11-13, component library: the dashboard moved from shadcn (Base UI, cmdk, vaul, `@shadcn/react`) to ui-sdk, keeping every class and token so the look doesn't change. The wrappers in `src/components/ui` keep their names and props. Popups now render where they're declared (no portals), so parent child-selectors must skip `[popover]`. A trigger's `render={<Button />}` renders a plain styled button so agents see each control once. The 2026-11-10 Drawer and chat-primitive decisions above are superseded: the Drawer is ui-sdk's, and the transcript scrolls with ui-sdk's ScrollArea `stickToEnd`.
- 2026-11-13, Linear redesign (Claude's pick, the owner wasn't watching the run): the whole dashboard moved to Linear's look, because the owner named Linear as the reference. That counted as a clear brief, so no variants were built behind a picker. Three directions were weighed. 1 Linear app, applied through tokens and the ui-sdk wrappers: neutrals, Inter, hairline cards, indigo only for focus and "on" (axis: closest to TASTE.md). 2 Dark only, the marketing site's `#08090a` everywhere with no light theme (axis: one mood). 3 Hairline columns, Home and lists without card surfaces, split by 1px rules like Linear's pricing page (axis: structure). Kept 1. Why: it follows the TASTE.md Linear section, keeps the light theme people already use, and changes no layout, so routes and behavior stay as they were. 2 would drop a working theme. 3 is the strongest runner-up for Home if it ever needs to feel lighter. Before and after: the PR for `zaki/dashboard-linear-redesign`.
- 2026-11-18, per-agent models: an agent's Settings tab has a Model section between Profile and "In shared chats". Each role (default, fast, vision) is one full-width select, "Global: <first model>" or "Custom", the same select pattern as the fields beside it (TASTE.md: one setting, one control). Custom opens the same chain editor as Settings > Models, extracted to `src/components/model-chain.tsx`, and starts as a copy of the global chain. The role hint sits above the select so the chain follows it directly. The owner asked for "default global or override", which counted as a clear brief inside the existing design, so no variants were built. No motion: it's a rarely changed setting and the chain appears at once.
- 2026-11-18, model chain editor rebuilt: a step is now a drag handle, one model search, a reasoning select and an X. The search lists every model connector's models in one place, grouped by connector, with the chain's other models on top, so picking a model picks its connector and the separate connector select is gone (Raycast does the same). Reorder is direct: drag the handle, or focus it and press the arrow keys; focus follows the step and a live region says where it moved. Rows slide 180 ms to their new place (FLIP, ease-out, off with reduced motion). This replaces the 2026-11-11 per-step actions menu. Picked by the owner from six prototypes over two rounds (round 2 was researched against OpenRouter, Vercel AI Gateway, Raycast and Cursor): "Drag to order" over "Primary and backups" and "Quiet table". On a phone a step is two lines (model, then reasoning) with a wider gap between steps so the pairs read as one. Model lists load the first time any search opens, not on page load.
